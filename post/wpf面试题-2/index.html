C# WinForm 和 WPF 中级面试题整理

1. 是否使用过委托，一般在何时使用委托？

✅面试简答（考场口述答案）

委托本质是对方法的抽象引用，允许将方法作为参数传递或存储。主要用于事件回调、跨线程UI更新（Dispatcher）以及通用算法策略（如Sort比较器）。现代开发中推荐使用泛型委托 Action/Func 替代自定义委托声明。

📚深入解析

  • 核心概念：委托是类型安全的函数指针，继承自 System.MulticastDelegate。它解耦了“调用者”与“执行逻辑”，实现观察者模式的基础。
  • 典型场景：
    • 事件驱动：按钮点击、串口数据到达通知。
    • 跨线程通信：WPF/WinForm 中子线程通过 Dispatcher.Invoke(Action) 更新 UI。
    • 策略模式/高阶函数：List<T>.Sort(Comparison<T>)、LINQ 的 Where(Func<T, bool>)。
  • 演进：早期需显式 delegate void MyDel(string s)；现在直接用 Action<string> 或 Func<int, string>，代码更简洁且框架统一。

  3. Action 和 Func 最多支持多少个泛型参数？

2. 是否使用过匿名委托及 Lambda 表达式？

✅面试简答（考场口述答案）

匿名委托是用 delegate 关键字内联定义的方法体；Lambda 是其语法糖，用 => 简化写法。两者本质都是编译器生成的委托实例，广泛用于 LINQ 查询和事件订阅，避免为简单逻辑单独命名方法。

📚深入解析

  • 匿名委托：delegate(int x) { return x * 2; }，可访问外部局部变量（闭包）。
  • Lambda 表达式：(x) => x * 2。编译器根据上下文推断类型，支持表达式体（单行返回值）和语句块（多行）。
  • 底层实现：编译器会生成一个隐藏类来捕获闭包变量，Lambda 变成该类的实例方法。若无闭包，则可能缓存为静态字段以避免重复分配。
  • 注意：在循环中使用 Lambda 捕获循环变量时需注意版本差异（C# 5+ 已修复 foreach 变量捕获问题，但 for 循环仍需小心）。

3. 是否使用过多线程，何时使用多线程，应注意什么？

✅面试简答（考场口述答案）

多线程用于耗时计算、IO操作和并行处理以避免UI卡顿。注意点包括：子线程不可直接操作UI控件（需用Dispatcher）、共享资源需同步（lock/Semaphore）、优先使用Task/async-await而非裸Thread。锁对象必须是引用类型，避免死锁。

📚深入解析

  • 使用场景：CPU密集型（图像处理）、IO密集型（文件/网络）、响应式UI。
  • WPF 线程模型：UI 线程拥有 Dispatcher，子线程更新 UI 必须封送：Dispatcher.Invoke(() => txt.Text = "ok")。推荐通过 MVVM 绑定 + INotifyPropertyChanged 自动同步。
  • 同步机制：
    • lock (Monitor)：最常用，注意锁粒度。
    • SemaphoreSlim：限制并发数。
    • Interlocked：原子操作，无锁高性能。
    • Concurrent 集合：线程安全容器。
  • 避坑指南：
    • 禁止 lock 值类型（装箱导致每次锁不同对象）。
    • 避免 Thread.Sleep 做同步，应使用信号量或 Task.Delay。
    • 优先 TAP (Task) 而非 APM/EAP，支持取消令牌和异常传播。

4. 异步编程（Async/Await）的理解？

✅面试简答（考场口述答案）

async/await 是基于 Task 的异步语法糖，编译器将其转为状态机。await 挂起当前方法但不阻塞线程，完成后恢复执行。UI 线程 await 后默认回到 UI 线程。返回类型应为 Task/Task，避免 async void（除事件外）。库代码建议 ConfigureAwait(false)。

📚深入解析

  • 状态机原理：async 方法被编译为实现 IAsyncStateMachine 的结构体，记录局部变量和执行点。await 注册回调，Task 完成时触发 MoveNext。
  • 上下文捕获：默认捕获 SynchronizationContext（WPF 中为 DispatcherSynchronizationContext），确保 await 后回到 UI 线程。类库中用 .ConfigureAwait(false) 跳过捕获，减少开销。
  • 返回值规范：
    • Task<T> / Task：标准异步返回。
    • ValueTask<T>：高频热路径优化，避免 Task 分配。
    • async void：仅用于事件处理器，异常无法被 try-catch 捕获，会导致进程崩溃。
  • CPU vs IO：IO 操作直接 await；CPU 密集计算用 Task.Run 包装后再 await。

5. 是否使用过反射，使用场景和目的？

✅面试简答（考场口述答案）

反射允许运行时动态获取类型元数据、创建实例和调用成员。常用于插件架构、ORM映射、序列化框架和单元测试私有方法。缺点是性能开销大且缺乏编译期检查，高频场景应缓存 MethodInfo 或使用表达式树优化。

📚深入解析

  • 核心 API：Type.GetType(), Activator.CreateInstance(), MethodInfo.Invoke(), PropertyInfo.GetValue()。
  • 应用场景：
    • 插件系统：扫描 DLL 加载实现特定接口的类。
    • 框架底层：EF Core 实体映射、Json.NET 属性序列化、MVC 路由特性解析。
    • AOP/代理：动态生成代理类实现日志/事务拦截。
  • 性能优化：
    • 缓存 Type/MethodInfo 到静态字典。
    • 使用 Delegate.CreateDelegate 将反射调用转为强类型委托。
    • 使用 Source Generators (C# 9+) 在编译期生成代码替代运行时反射。

6. 是否使用过泛型及泛型约束，使用场景？

✅面试简答（考场口述答案）

泛型实现类型安全的代码复用，避免装箱拆箱。约束（where）限制 T 的能力以保证编译安全。常见约束有 class/struct/new()/基类/接口。例如 where T : People, new() 确保 T 是 People 子类且有无参构造。

📚深入解析

  • 优势：类型安全（编译期检查）、性能（值类型免装箱）、代码复用（一套逻辑适用多类型）。
  • 约束详解：
    • where T : class / struct：引用/值类型。
    • where T : new()：必须有公共无参构造（须放最后）。
    • where T : BaseClass / IInterface：继承/实现关系。
    • where T : notnull (C# 8+)：非空约束。
    • where T : U：裸类型约束。
  • JIT 行为：值类型泛型为每种类型生成专用本机代码；引用类型泛型共享同一份本机代码（指针大小相同）。

7. 是否使用 LINQ，使用场景？

✅面试简答（考场口述答案）

LINQ 提供统一的查询语法，支持内存集合、数据库、XML等数据源。核心特性是延迟执行，只有遍历或 ToList 时才真正运行。常用操作符包括 Where/Select/OrderBy/GroupBy。注意区分 IEnumerable（内存）和 IQueryable（数据库）的执行差异。

📚深入解析

  • 延迟执行：查询定义时不执行，枚举时触发。优点是可组合查询条件，缺点是多次枚举会重复执行（如数据库查询）。
  • 两种语法：方法语法（链式调用）vs 查询语法（SQL风格），编译器最终都转为方法调用。
  • IQueryable vs IEnumerable：
    • IEnumerable：LINQ to Objects，客户端过滤，拉取全部数据。
    • IQueryable：LINQ to SQL/EF，服务端过滤，生成 SQL 语句。
  • 性能陷阱：避免在 IQueryable 后混用客户端方法导致全表扫描；分页用 Skip/Take；投影只选所需列。

8. 单例模式的实现方式？

✅面试简答（考场口述答案）

单例保证全局唯一实例。饿汉式利用静态字段初始化，CLR保证线程安全；懒汉式推荐用 Lazy<T> 实现线程安全的延迟加载。避免手写双检锁除非极端性能需求。构造函数必须私有。

📚深入解析

  • 饿汉式：private static readonly Singleton _inst = new(); 简单安全，但启动即占用资源。
  • 懒汉式（推荐）：private static readonly Lazy<Singleton> _inst = new(() => new Singleton()); 默认线程安全（LazyThreadSafetyMode.ExecutionAndPublication）。
  • 双检锁：lock + volatile + 双重 null 检查。易出错，仅在 .NET Framework 旧版本或特殊场景考虑。
  • DI 容器中的单例：services.AddSingleton<T>()，由容器管理生命周期，无需手写单例代码。

  1. 单例模式有什么缺点？（测试难、隐藏依赖、多线程竞争）
  2. Lazy<T> 的线程安全模式有哪些？
  3. 如何在单元测试中重置单例状态？

9. 如何理解面向对象及设计原则？

✅面试简答（考场口述答案）

OOP 通过封装、继承、多态抽象现实问题。设计遵循 SOLID 原则：单一职责、开闭、里氏替换、接口隔离、依赖倒置。并非所有场景都需 OOP，简单脚本可用过程式，复杂业务才抽象建模，避免过度设计。

📚深入解析

  • 三大特征：封装（隐藏细节）、继承（复用/is-a）、多态（运行时行为差异化）。
  • SOLID 原则：
    • SRP：一个类只做一件事。
    • OCP：对扩展开放，对修改关闭。
    • LSP：子类可替换父类而不破坏程序。
    • ISP：接口小而专，不强迫实现无关方法。
    • DIP：依赖抽象而非具体实现。
  • 务实观点：小型工具/一次性代码不必强行 OOP；领域模型复杂时再用 DDD/OOP 建模。

  2. 举例说明违反里氏替换原则的代码？

10. 如何理解三层架构？

✅面试简答（考场口述答案）

三层分为 UI（展示）、BLL（业务逻辑）、DAL（数据访问），单向依赖以实现高内聚低耦合。通常增加 Entity/Model 层传递数据。优点是职责清晰、可独立测试、易于替换底层实现。现代架构常结合 DI 和 DDD 演进。

📚深入解析

  • 分层职责：
    • UI：交互与展示，不含业务规则。
    • BLL：核心业务编排、校验、事务控制。
    • DAL：CRUD、SQL/ORM 操作。
    • Model/Entity：跨层数据载体。

15. 托管代码与非托管代码的区别？

✅面试简答（考场口述答案）

托管代码（C#/VB）编译为 IL，由 CLR 管理内存、安全和异常；非托管代码（C/C++）编译为机器码，自行管理资源。C# 通过 P/Invoke 或 C++/CLI 调用非托管代码。托管代码跨平台、安全；非托管代码性能高、贴近硬件。

📚深入解析

  • 托管代码：享受 GC、JIT、类型安全、CAS 等服务。独立于平台和语言。
  • 非托管代码：Win32 API、COM、原生 DLL。需手动 malloc/free，易内存泄漏。
  • 互操作：
    • P/Invoke (DllImport)：调用 C 导出函数。
    • COM Interop：调用 COM 组件。
    • C++/CLI：混合编程桥梁。
  • 性能：跨边界调用有 marshaling 开销，高频调用需批处理或固定内存。

16. 托管资源与非托管资源的释放？

✅面试简答（考场口述答案）

托管资源由 GC 自动回收；非托管资源（文件句柄、连接等）必须显式释放。实现 IDisposable 接口并用 using 语句是标准做法。若类持有非托管资源，还需实现终结器作为兜底，并调用 GC.SuppressFinalize 避免重复回收。

📚深入解析

  • Dispose Pattern： 
    public void Dispose() { Dispose(true); GC.SuppressFinalize(this); }
protected virtual void Dispose(bool disposing) {
    if (disposing) { /* 释放托管资源 */ }
    /* 释放非托管资源 */
}
~MyClass() { Dispose(false); }
  • using 语句：编译为 try-finally 块，确保异常时也调用 Dispose。
  • SafeHandle：推荐用 SafeHandle 封装非托管句柄，比 IntPtr + 终结器更安全可靠。
  • GC.SuppressFinalize：告知 GC 无需调用终结器，提升回收性能（终结器对象需两次 GC 才能回收）。

22. C# 访问修饰符详解？

✅面试简答（考场口述答案）

    • protected internal：同程序集 OR 派生类（并集）。
    • private protected：同程序集 AND 派生类（交集）。
  • 其他修饰符：static, sealed, abstract, virtual, override, readonly, const。
  • 规则：成员可见性不能高于所在类型的可见性。

25. String 和 StringBuilder 的区别？

✅面试简答（考场口述答案）

String 不可变，修改创建新对象；StringBuilder 可变，内部字符数组原地修改。少量拼接用 string（编译器优化），循环大量拼接必须用 StringBuilder 避免 GC 压力。String 是引用类型但相等性比较值。

📚深入解析

  • String 不可变性：线程安全，可作哈希键，但拼接产生临时对象。编译器对常量拼接优化为 Concat。
  • StringBuilder：默认容量 16，不足时扩容（通常翻倍）。Append 在原缓冲区操作。
  • 选择指南：
    • 固定次数/少量拼接 → string / $"" / string.Concat。
    • 循环/未知次数拼接 → StringBuilder。
    • .NET Core 3.0+ 可用 string.Create 或 Span<char> 极致优化。
  • 相等性：== 重载为值比较；ReferenceEquals 比较引用。

    • 声明式：界面即文档，易于维护和协作。

    • 集成：深度支持数据绑定、资源字典、模板、动画。
  • 跨平台：WPF、UWP、WinUI、MAUI、Avalonia 均使用 XAML，学习一次多处受益。

28. 依赖属性（DependencyProperty）详解？

✅面试简答（考场口述答案）

依赖属性是 WPF 属性系统的核心，支持绑定、动画、样式、值继承、变更通知和验证。相比 CLR 属性，它节省内存（未设置不占实例空间）、功能丰富。通过 DependencyProperty.Register 注册，用 GetValue/SetValue 访问。专为 WPF 绑定体系设计。

📚深入解析

  • 核心特性：
    • 值优先级：本地值 > 样式 > 模板 > 继承 > 默认值。
    • 变更通知：PropertyChangedCallback。
    • 值验证：ValidateValueCallback / CoerceValueCallback。
    • 内存优化：稀疏存储，仅存储非默认值。
  • 定义模式： 
    public static readonly DependencyProperty TitleProperty =
    DependencyProperty.Register("Title", typeof(string), typeof(MyControl),
        new PropertyMetadata("", OnTitleChanged));
public string Title { get => (string)GetValue(TitleProperty); set => SetValue(TitleProperty, value); }
  • vs CLR 属性：CLR 属性是字段包装，无绑定/动画能力；依赖属性是 WPF 基础设施。

一、类和结构体的区别是什么

✅面试简答（考场口述答案）

核心区别在于类型系统分类和内存模型：

  1. 类型本质：class 是引用类型，struct 是值类型。
  2. 内存分配：类实例分配在**堆（Heap）上，变量存引用；结构体通常分配在栈（Stack）**上（作为局部变量时）或内联在包含它的对象中，变量直接存数据。
  3. 赋值语义：类赋值是拷贝引用（浅拷贝），修改一个会影响另一个；结构体赋值是拷贝整个数据（深拷贝），互不影响。
  4. 继承性：类支持继承和多态；结构体不能继承其他类或结构体（但可实现接口）。
  5. 默认构造：类可以没有无参构造函数；结构体始终有一个隐式的无参构造函数（将所有字段初始化为零值），且在 C# 10 之前不能自定义无参构造。

📚深入解析

1. 详细对比表

特性 Class (类) Struct (结构体)
类型 引用类型 值类型
内存位置 堆 (Heap) 栈 (Stack) / 内联
赋值行为 拷贝地址 拷贝数据
继承 支持单继承 不支持继承 (sealed)
接口 可实现 可实现
null 值 可以为 null 不能为 null (除非 Nullable)
析构函数 支持 (~ClassName) 不支持
字段初始化 可在声明时初始化 C# 10+ 支持，旧版受限
性能特征 GC 管理，有分配开销 无 GC 压力，拷贝开销随大小增加

2. 关键陷阱与注意事项

  • 可变结构体是万恶之源：由于结构体是值拷贝，如果你修改了一个从属性返回的结构体字段（如 myObj.Point.X = 10;），你修改的只是副本，原对象不会改变。这会导致极其隐蔽的 Bug。最佳实践：结构体应设计为不可变（Immutable）。
  • 装箱/拆箱开销：当结构体被当作 object、接口类型或调用未重写的虚方法（如 ToString()）时，会发生装箱。频繁装箱会抵消结构体的性能优势。
  • 大小限制：微软官方建议结构体大小控制在 16 字节以内。过大的结构体在赋值、传参时的拷贝成本可能超过堆分配的开销，此时应改用 class。
  • this 的安全性：在结构体方法中，this 是一个值而非引用。为了防止意外修改，C# 引入了 readonly struct 和 in 参数修饰符。

3. 代码示例：赋值差异 

// === Class 演示 ===
class PersonClass { public string Name; }
var p1 = new PersonClass { Name = "Alice" };
var p2 = p1;      // 拷贝引用
p2.Name = "Bob";
Console.WriteLine(p1.Name); // 输出: Bob (p1 也被修改了)

// === Struct 演示 ===
struct PointStruct { public int X; public int Y; }
var s1 = new PointStruct { X = 1, Y = 2 };
var s2 = s1;      // 拷贝整个数据
s2.X = 99;
Console.WriteLine(s1.X); // 输出: 1 (s1 不受影响)

4. 何时使用 Struct？

  • ✅ 表示一个单一的值（如坐标 Point、颜色 Color、金额 Money）。
  • ✅ 数据量小（< 16 bytes）且生命周期短。
  • ✅ 需要高性能、避免 GC 压力的场景（如图形渲染、高频交易）。
  • ✅ 与外部非托管代码交互（Interop）。
  • ❌ 不要用来建模业务实体（Entity），不要用可变结构体。

💡面试延伸追问（预判面试官后续提问）

  1. 什么是 readonly struct？它解决了什么问题？
    • 考点：防止结构体被意外修改；允许编译器对 in 参数传递进行优化（避免防御性拷贝）；保证线程安全。
  2. ref struct 是什么？和普通 struct 有什么区别？
    • 考点：ref struct 只能存在于栈上，不能被装箱、不能作为泛型参数、不能存储在堆上（如类字段、数组元素）。典型代表：Span<T>, ReadOnlySpan<T>。用于极致性能和安全内存访问。
  3. 结构体可以实现接口吗？实现接口时有什么需要注意的？
    • 考点：可以实现。但如果将结构体赋值给接口变量，会发生装箱。为避免装箱，应在泛型约束中使用 where T : IMyInterface，这样 JIT 会生成针对该结构体的特化代码，直接在栈上调用接口方法。
  4. C# 10 对结构体做了哪些改进？
    • 考点：允许自定义无参构造函数；允许在声明时初始化字段/属性；支持 record struct（不可变结构体的简洁语法）。这些改进让结构体更易用、更安全。

二、什么是分部类

✅面试简答（考场口述答案）

**分部类（Partial Class）**允许将一个类、结构体或接口的定义拆分到多个文件中。在编译时，C# 编译器会将这些部分合并成一个完整的类型。

  • 关键字：partial。
  • 核心作用：
    1. 代码分离：将自动生成的代码（如 EF Core 实体、WPF/XAML 后台代码）与手写业务逻辑分开，避免修改生成代码导致丢失。
    2. 团队协作：允许多个开发者同时处理同一个大型类的不同部分（较少见，通常通过接口或继承解决）。
    3. 保持整洁：将庞大的类按功能模块拆分到不同文件，提高可读性。

📚深入解析

1. 语法规则与约束

要成功合并为一个类，所有分部声明必须满足以下条件：

  • 同一程序集和模块：必须在同一个 .dll 或 .exe 中。
  • 相同的访问修饰符：如果一部分是 public，其他部分也必须是 public。
  • 相同的基类和接口：所有部分继承的基类和实现的接口最终会合并。
  • 嵌套类型：如果一个部分是嵌套类，其他部分也必须是嵌套在同一个外部类中。
// File: User.Part1.cs
public partial class User
{
    public int Id { get; set; }
    public string Name { get; set; }
}

// File: User.Part2.cs
public partial class User
{
    public void Validate()
    {
        if (string.IsNullOrEmpty(Name)) throw new Exception("Name is required");
    }
}
// 编译后等同于一个包含 Id, Name 和 Validate 方法的完整 User 类

2. 典型应用场景

  • ASP.NET Core / Entity Framework： EF Core 生成的实体类通常标记为 partial。你可以创建另一个同名分部类来添加自定义验证逻辑、非映射属性（Non-mapped properties）或业务方法，而不用担心重新生成数据库模型时覆盖你的代码。
  • WPF / WinForms / MAUI： UI 框架会自动生成 .g.i.cs 文件来处理 XAML 中的控件绑定和初始化。开发者手写的代码放在另一个分部文件中。这是 partial 最经典的应用。
  • 大型类的模块化： 如果一个类过于庞大（虽然这通常是设计不良的信号），可以将其拆分为 User.Properties.cs, User.Methods.cs, User.Events.cs 等。

3. 分部方法（Partial Methods - C# 9 之前限制较多，C# 9+ 增强）

  • 定义：在分部类中声明但没有实现的方法。
  • 旧版行为：如果没有任何部分提供实现，编译器会在编译时直接移除该方法及其所有调用，零开销。
  • 新版行为（C# 9+）：允许分部方法有返回值、out 参数，且必须有实现（或者像以前一样如果没有实现则被移除，取决于具体上下文和可访问性）。主要用于代码生成器（Source Generators）在编译时注入逻辑。

4. 注意事项

  • 特性（Attributes）：如果在多个分部上应用了相同的特性，它们会被合并。但如果特性不允许重复，可能会报错。
  • 泛型约束：泛型类型的约束可以在不同的分部中指定，但最终合并后的约束必须一致且不冲突。
  • 调试体验：在 Visual Studio 中调试时，IDE 能够智能地识别并跳转到正确的物理文件，开发者通常感觉不到它是拆分的。

💡面试延伸追问（预判面试官后续提问）

  1. 分部类（Partial Class）和继承（Inheritance）有什么区别？什么时候用哪个？
    • 考点：分部类是同一个类型的物理拆分，共享私有成员和状态；继承是不同类型的逻辑扩展。如果需要扩展第三方库的类且无法修改源码，应使用继承或扩展方法，而不是分部类（因为你无法控制对方的源码文件）。分部类主要用于“自己生成的代码”和“自己手写的代码”共存。
  2. 什么是 Source Generators（源代码生成器）？它和分部类有什么关系？
    • 考点：Source Generators 是 Roslyn 编译器的一项功能，可以在编译时分析代码并生成新的 C# 文件。生成的代码通常作为分部类的一部分与原始代码合并。这是现代 .NET（如 .NET 6+ Minimal API, Dapper AOT）提高性能的重要手段。
  3. 分部类可以跨项目吗？
    • 考点：不可以。分部类必须在同一个程序集（Assembly）内。跨项目复用代码应使用类库引用、NuGet 包或继承/组合模式。
  4. 如果两个分部类中定义了同名的私有字段，会发生什么？
    • 考点：编译错误。因为它们在逻辑上是同一个类，不能在同一作用域内重复定义成员。

三、new关键字的作用是什么

✅面试简答（考场口述答案）

在 C# 中，new 关键字主要有三种用途：

  1. 创建对象实例：调用构造函数，在堆上分配内存并初始化对象（针对引用类型）或在栈/内联位置初始化数据（针对值类型）。
  2. 隐藏基类成员（Shadowing）：当子类定义了一个与基类同名的成员时，使用 new 修饰符显式隐藏基类成员，而不是重写（Override）它。
  3. 泛型约束：在泛型定义中使用 where T : new()，约束类型参数必须具有公共的无参构造函数。

📚深入解析

1. 实例化对象 (Operator)

这是最常见的用法。

  • 对于引用类型 (class)：var obj = new MyClass();
    • 在托管堆（Heap）上分配内存。
    • 调用构造函数初始化字段。
    • 返回指向该内存地址的引用。
  • 对于值类型 (struct)：var s = new MyStruct();
    • 通常在栈上分配（或内联）。
    • 将所有字段初始化为默认值（0, null, false）。
    • 注意：即使不调用 new，值类型也有默认值，但调用 new 可以确保所有字段被正确初始化，特别是当结构体有自定义构造函数时。

2. 隐藏基类成员 (Modifier)

当子类中有一个方法与基类方法签名完全相同，但你不想实现多态（即不希望通过基类引用调用到子类的方法）时，使用 new。

public class Base
{
    public void Show() { Console.WriteLine("Base"); }
}

public class Derived : Base
{
    // 使用 new 隐藏基类的 Show 方法
    public new void Show() { Console.WriteLine("Derived"); }
}

// 测试
Base b = new Derived();
b.Show(); // 输出: "Base" (因为 Show 不是虚方法，且被 new 隐藏了，编译时绑定到 Base)

Derived d = new Derived();
d.Show(); // 输出: "Derived"
  • 对比 override：
    • override 用于虚方法（virtual），实现运行时多态。
    • new 用于非虚方法或故意切断多态链，属于编译时绑定。
    • 如果不写 new 也不写 override，编译器会报警告（CS0108），建议显式加上 new 以表明意图。

3. 泛型约束 (Constraint)

用于限制泛型类型 T 必须能够被实例化。

public class Factory<T> where T : new()
{
    public T CreateInstance()
    {
        return new T(); // 只有加了 new() 约束，这里才能编译通过
    }
}
  • 注意：new() 约束要求必须是公共的无参构造函数。如果类只有带参构造或私有构造，则无法满足此约束。

💡面试延伸追问（预判面试官后续提问）

  1. new 隐藏成员和 override 重写成员的本质区别是什么？
    • 考点：多态性。override 是动态绑定（Runtime Binding），根据对象的实际类型调用方法；new 是静态绑定（Compile-time Binding），根据变量的声明类型调用方法。面试中常考“基类引用指向子类对象”时的调用结果。
  2. 在泛型中，where T : new() 有什么局限性？
    • 考点：它只能调用无参构造函数。如果需要传递参数，通常需要使用 Activator.CreateInstance（性能较差）或使用工厂模式、依赖注入容器来解决。
  3. new 关键字在内存管理中扮演什么角色？它与 GC 有什么关系？
    • 考点：new 触发内存分配。对于引用类型，频繁 new 会产生大量短期对象，增加 Gen 0 GC 的频率。理解 new 的成本有助于优化高性能代码（如使用对象池 ObjectPool 避免频繁 new）。
  4. 什么是“阴影”（Shadowing）？为什么 C# 允许这种行为？
    • 考点：阴影是指子类重新定义了基类已有的成员。C# 允许它是为了版本控制兼容性：如果基类在新版本中添加了一个方法，而子类之前已经有一个同名方法，使用 new 可以避免子类行为被意外改变，保证向后兼容。

四、static关键字的作用是什么

✅面试简答（考场口述答案）

static 关键字用于声明属于类型本身而不是属于类型特定实例的成员。

  1. 静态成员：包括字段、方法、属性、事件等。它们被所有实例共享，通过类名直接访问（如 Math.PI），不需要创建对象。
  2. 静态构造函数：用于初始化静态字段，由 CLR 在第一次访问该类时自动调用，且只执行一次。
  3. 静态类：只能包含静态成员，不能被实例化，也不能被继承。通常用于工具类（如 Console, Math）。
  4. 核心特点：生命周期伴随应用程序域（AppDomain）或进程，直到程序结束才释放。

📚深入解析

1. 内存与生命周期

  • 存储位置：静态字段存储在**高频率堆（High-Frequency Heap）**或专门的静态存储区，不属于某个对象的堆内存。
  • 生命周期：从类被加载（JIT 编译触发或首次访问）开始，直到应用程序域卸载或进程终止。因此，静态变量如果引用了大型对象，极易导致内存泄漏。

2. 静态构造函数 (Static Constructor)

  • 语法：static ClassName() { }，无参数，无访问修饰符。
  • 执行时机：CLR 保证在创建第一个实例或引用任何静态成员之前执行。
  • 线程安全：CLR 保证静态构造函数在多线程环境下只执行一次，是天然的线程安全初始化方式。
  • 性能陷阱：如果静态构造函数逻辑复杂或耗时，会阻塞所有尝试访问该类的线程，导致启动变慢或死锁风险。
public class DatabaseConfig
{
    public static string ConnectionString;

    // 静态构造函数：只运行一次
    static DatabaseConfig()
    {
        Console.WriteLine("Loading config...");
        ConnectionString = LoadFromConfigFile(); 
    }
}

3. 静态类 (Static Class)

  • 限制：
    • 不能实例化 (new StaticClass() 报错)。
    • 不能包含实例构造函数。
    • 不能被继承（隐式 sealed + abstract）。
    • 只能包含静态成员。
  • 用途：存放纯函数、常量、扩展方法。例如 System.Math, System.Console。

4. 静态扩展方法 (Extension Methods)

  • 本质：静态类中的静态方法，但第一个参数带有 this 修饰符。
  • 作用：在不修改源码的情况下为现有类型“添加”方法。
  • 注意：扩展方法优先级低于实例方法；如果实例方法存在，编译器优先调用实例方法。
public static class StringExtensions
{
    // 静态方法 + this 参数 = 扩展方法
    public static bool IsNullOrEmpty(this string str)
    {
        return string.IsNullOrEmpty(str);
    }
}
// 调用： "hello".IsNullOrEmpty();

5. 常见陷阱与最佳实践

  • 线程安全：静态字段被所有线程共享。如果多个线程同时修改一个静态非只读字段，必须使用锁（lock）或线程安全集合（ConcurrentDictionary）。
  • 单元测试困难：依赖静态成员的代码很难进行 Mock（模拟），因为无法替换静态行为。现代开发倾向于使用**依赖注入（DI）**替代静态单例。
  • 不要滥用静态状态：除了配置、日志记录器等全局唯一资源外，尽量避免使用可变的静态字段，这会破坏代码的可维护性和可测试性。

💡面试延伸追问（预判面试官后续提问）

  1. 静态构造函数和普通构造函数的执行顺序是怎样的？
    • 考点：先执行静态构造函数（仅一次），再执行实例构造函数（每次 new 都执行）。如果类中有静态字段初始化器，它们的执行顺序通常与代码书写顺序一致，且在静态构造函数之前。
  2. 为什么扩展方法必须是静态的？
    • 考点：扩展方法本质上只是语法糖，编译器将其转换为普通的静态方法调用。它不需要对象状态，只需要操作传入的参数。
  3. 静态类可以被垃圾回收（GC）吗？
    • 考点：不能单独回收。静态成员的生命周期绑定到 AppDomain。只有当整个 AppDomain 卸载（在 .NET Core/5+ 中通常是进程结束）时，静态占用的内存才会被释放。
  4. const 和 static readonly 有什么区别？
    • 考点：
      • const：编译时常量，值嵌入到调用方的 IL 中，修改后需重新编译所有引用项目。只能是基本类型或字符串。
      • static readonly：运行时常量，在静态构造函数或声明时赋值，值是动态获取的，修改后只需重新编译定义方。可以是任何类型。

五、什么是静态类

✅面试简答（考场口述答案）

**静态类（Static Class）**是 C# 中一种特殊的类，它不能被实例化，只能包含静态成员。

  • 核心特征：
    1. 不能实例化：不能使用 new 关键字创建对象。
    2. 隐式密封且抽象：编译器会自动将其标记为 sealed（不可继承）和 abstract（不可实例化）。
    3. 仅含静态成员：只能包含静态字段、方法、属性、事件等，不能有实例构造函数或实例成员。
    4. 加载时机：在程序首次引用该类时由 CLR 自动加载，生命周期伴随整个应用程序域。
  • 典型用途：存放工具方法（如 Math）、扩展方法、全局常量或配置信息。

📚深入解析

1. 语法定义与限制 

// 必须使用 static 关键字修饰类
public static class UtilityHelper
{
    // ✅ 允许：静态字段
    private static readonly string AppName = "MyApp";

    // ✅ 允许：静态方法
    public static int Add(int a, int b)
    {
        return a + b;
    }

    // ❌ 错误：静态类不能包含实例构造函数
    // public UtilityHelper() { }

    // ❌ 错误：静态类不能包含实例成员
    // public string InstanceField; 
}

2. 底层原理

  • 编译器行为：当你声明 static class 时，C# 编译器会在生成的 IL（中间语言）中同时添加 abstract 和 sealed 标志。
    • abstract：防止被实例化。
    • sealed：防止被继承。
  • 内存管理：静态类的静态字段存储在**高频率堆（High-Frequency Heap）**或专门的静态存储区。它们不属于任何对象实例，因此不受 GC 对普通对象的回收逻辑影响，直到进程结束或 AppDomain 卸载才会释放。

3. 静态类 vs 普通类（全静态成员）

虽然你可以创建一个普通类并把所有成员设为 static，但使用 static class 有以下优势：

  1. 编译时检查：编译器会强制确保你不会意外添加实例成员或构造函数。
  2. 语义清晰：明确告诉其他开发者“这个类只是功能的集合，没有状态”，提高代码可读性。
  3. 性能微优：CLR 对静态类的加载和初始化有特定的优化路径。

4. 常见应用场景

场景 示例 说明
工具类 System.Math, System.IO.Path 提供无状态的纯函数计算。
扩展方法容器 LinqExtensions C# 规定扩展方法必须定义在静态类中。
全局配置/常量 AppSettings 存储应用启动时加载的一次性配置。
日志记录器 Logger 提供全局统一的日志入口（注意线程安全）。

5. 潜在风险与最佳实践

  • 线程安全：静态类中的可变静态字段（static non-readonly）会被所有线程共享。如果多个线程同时写入，必须使用锁（lock）或线程安全集合。
  • 单元测试困难：依赖静态类的代码难以进行 Mock（模拟），因为无法替换其实现。在现代架构（如 ASP.NET Core）中，倾向于使用**依赖注入（DI）**的单例服务来替代静态工具类，以提高可测试性。
  • 避免“上帝类”：不要把所有不相关的工具方法都塞进一个巨大的静态类中，应按功能模块拆分（如 StringHelper, DateHelper）。

💡面试延伸追问（预判面试官后续提问）

  1. 静态类可以有构造函数吗？
    • 考点：可以有静态构造函数（static UtilityHelper() {}），用于初始化静态字段。但不能有实例构造函数。静态构造函数由 CLR 在第一次访问该类时自动调用，且只执行一次。
  2. 静态类和单例模式（Singleton）有什么区别？
    • 考点：
      • 静态类：由 CLR 管理生命周期，无法实现接口，无法懒加载（通常随首次引用加载），难以 Mock。
      • 单例：是一个普通的类实例，可以实现接口，支持懒加载，可以通过 DI 容器管理，更容易进行单元测试和替换实现。现代开发更推荐单例而非静态类。
  3. 扩展方法为什么必须放在静态类中？
    • 考点：扩展方法本质上是编译器语法糖，最终会被编译成普通的静态方法调用。编译器要求宿主类必须是静态的，以确保该方法不会依赖于任何实例状态，保证调用的纯粹性和安全性。
  4. 如果我在静态类中定义了一个非静态方法，会发生什么？
    • 考点：编译错误（CS0708）。编译器会明确提示“静态类中不能声明实例成员”。这是静态类最严格的约束之一。

六、null赋值运算符、null合并运算符和null条件运算符的作用是什么

✅面试简答（考场口述答案）

这三个运算符是 C# 处理 null 值的核心语法糖，旨在简化代码并提高安全性：

  1. Null 合并运算符 (??)：如果左侧操作数为 null，则返回右侧操作数；否则返回左侧。常用于设置默认值。
  2. Null 条件运算符 (?.)：也称为“安全导航运算符”。如果左侧对象为 null，则整个表达式直接返回 null，而不会抛出 NullReferenceException。常用于链式调用前的判空。
  3. Null 赋值运算符 (??=)：C# 8.0 引入。仅当左侧变量为 null 时，才将右侧的值赋给它。是 if (x == null) x = value; 的简写。

(注：通常还有一个与之配套的 Null 条件成员访问运算符 (?[])，用于数组或索引器的安全访问)

📚深入解析

1. Null 合并运算符 (??)

  • 语法：a ?? b
  • 逻辑：等价于 a != null ? a : b。
  • 特点：支持链式调用，可以连续提供多个备选值，直到找到一个非 null 的值。
  • 应用场景：配置读取、参数默认值、字典查找。
string input = null;
string result = input ?? "Default Value"; // result = "Default Value"

// 链式使用：优先取 config，其次取 env，最后取默认
string dbConn = config.ConnectionString 
             ?? Environment.GetEnvironmentVariable("DB_CONN") 
             ?? "Server=localhost;";

2. Null 条件运算符 (?. 和 ?[])

  • 语法：obj?.Property 或 array?[index]
  • 逻辑：
    • 如果 obj 为 null，表达式结果为 null（即使 Property 是非 nullable 类型，结果也会提升为 Nullable<T>）。
    • 如果 obj 不为 null，则正常访问 Property。
  • 核心价值：避免冗长的 if (obj != null) 判断，防止空指针异常。
  • 注意返回值类型：如果属性是值类型（如 int），obj?.Count 的返回类型会变成 int? (Nullable)。
List<string> names = null;

// 传统写法
int count1 = names != null ? names.Count : 0;

// 现代写法 (注意 Count 是 int，所以结果是 int?)
int? count2 = names?.Count; 

// 结合 ?? 使用，完美解决默认值问题
int finalCount = names?.Count ?? 0; // 如果 names 为 null，count 为 0

3. Null 赋值运算符 (??=)

  • 语法：a ??= b
  • 逻辑：等价于 a = a ?? b。
  • 优势：
    1. 简洁：减少重复代码。
    2. 性能/副作用优化：左侧表达式 a 只计算一次。如果 a 是一个复杂的属性访问器或方法调用，使用 ??= 比 a = a ?? b 更安全且高效。
private List<string> _items;

public List<string> Items
{
    get
    {
        // 懒加载模式：只有当 _items 为 null 时才创建新列表
        _items ??= new List<string>(); 
        return _items;
    }
}

4. 综合对比表

运算符 名称 作用 等价逻辑
?? Null 合并 取第一个非 null 值 a != null ? a : b
?. Null 条件 安全访问成员 a == null ? null : a.Member
??= Null 赋值 为空时赋值 if (a == null) a = b

💡面试延伸追问（预判面试官后续提问）

  1. ?. 运算符在处理值类型（如 int）时，返回类型是什么？
    • 考点：返回的是对应的可空值类型（Nullable<T> 或 T?）。例如 DateTime? dt = obj?.CreateDate;。如果需要还原为非空类型，必须配合 ?? 使用，如 obj?.CreateDate ?? DateTime.MinValue。
  2. ?? 和 ?: (三元运算符) 有什么区别？为什么推荐用 ??？
    • 考点：?? 语义更清晰，专门针对 null 检查；?: 是通用条件判断。?? 还可以链式使用（a ?? b ?? c），而三元运算符嵌套起来可读性极差。此外，?? 在左侧不为 null 时不会计算右侧表达式（短路求值）。
  3. 在多线程环境下，??= 是线程安全的吗？
    • 考点：不是。虽然左侧只计算一次，但如果两个线程同时发现 _items 为 null，它们可能会分别创建新的 List 实例，导致其中一个被覆盖或资源浪费。在多线程懒加载场景下，应使用 Lazy<T> 或 Interlocked.CompareExchange。
  4. 什么是 ! (Null Forgiving Operator / 空值忽略运算符)？它和 ?. 有什么关系？
    • 考点：C# 8.0 引入的可空引用类型特性。obj!.Property 告诉编译器“我确定 obj 不为 null，请不要警告我”。它与 ?. 相反，?. 是防御性的，! 是强制性的（仅影响编译期静态分析，不影响运行时行为）。

七、什么是封装，封装和数据隐藏是相同的概念吗，封装和抽象有什么区别

✅面试简答（考场口述答案）

**封装（Encapsulation）**是将数据（字段）和操作数据的方法（行为）捆绑在一个单元（类）中，并控制外部对内部成员的访问权限。

  1. 封装 vs 数据隐藏：
    • 不完全相同。数据隐藏是封装的手段/结果，而封装是一个更广泛的概念。
    • 封装不仅包含“隐藏数据”（通过 private），还包含“暴露接口”（通过 public 方法）。它的核心目的是保护内部状态的完整性，并提供统一的交互方式。
  2. 封装 vs 抽象：
    • 封装关注的是**“如何隐藏实现细节”（How to hide），侧重于安全性和边界控制**（例如：用 private 字段配合 public 属性）。
    • 抽象关注的是**“应该暴露什么功能”（What to expose），侧重于简化复杂性**，让用户只关心接口而不关心底层逻辑（例如：定义接口 IShape，用户只需调用 Draw()，无需知道是画圆还是画方）。

一句话总结：封装是把东西包起来并加锁（保护内部），抽象是提供一个简单的遥控器（简化使用）。

📚深入解析

1. 封装（Encapsulation）的深度理解

封装不仅仅是把变量设为 private，它包含两个层面：

  • 信息隐藏（Information Hiding）：防止外部代码直接修改对象的内部状态，避免对象进入无效状态。
  • 接口聚合（Interface Aggregation）：将相关的数据和行为组织在一起，形成高内聚的模块。

经典示例：属性（Property）

public class BankAccount
{
    private decimal _balance; // 数据隐藏：外部无法直接修改余额

    public decimal Balance 
    { 
        get { return _balance; } 
    }

    // 封装行为：通过方法控制状态变更，确保业务规则（如余额不能为负）
    public void Deposit(decimal amount)
    {
        if (amount <= 0) throw new ArgumentException("Amount must be positive");
        _balance += amount;
    }
}

如果没有封装，外部可以直接 _balance = -1000，导致系统崩溃。

2. 封装与数据隐藏的区别

维度 数据隐藏 (Data Hiding) 封装 (Encapsulation)
定义 限制对数据的直接访问 将数据和行为绑定，并控制访问
范围 仅是封装的一个子集 包含数据隐藏 + 行为暴露
目的 防止数据被意外篡改 提高模块化、安全性、可维护性
实现 private, protected 等修饰符 类、属性、方法、访问修饰符的组合

结论：你可以实现数据隐藏而不完全实现封装（例如 C 语言的结构体配合全局函数），但在 OOP 中，封装必然包含数据隐藏。

3. 封装与抽象的区别

这是面试中最容易混淆的两个概念，可以通过以下维度区分：

维度 封装 (Encapsulation) 抽象 (Abstraction)
核心问题 如何保护内部实现？ 什么功能需要对外提供？
侧重点 内部视角：保护类的内部状态不被破坏。 外部视角：简化用户的使用复杂度。
实现手段 访问修饰符 (private, public)、属性。 抽象类 (abstract class)、接口 (interface)。
例子 汽车引擎的内部零件被外壳包裹，你摸不到活塞。 汽车方向盘和油门，你只需知道踩油门车会走，无需知道发动机原理。

形象类比：

  • 封装：像一个药胶囊。它把苦味的药粉（复杂数据/逻辑）包在光滑的外壳里，你吞下去就行，不会直接接触药粉，也不会被苦到。
  • 抽象：像电视遥控器。你只需要按“音量+”键，不需要知道内部电路是如何调节电压来改变声音大小的。

💡面试延伸追问（预判面试官后续提问）

  1. 为什么 C# 推荐使用属性（Property）而不是公共字段（Public Field）？
    • 考点：属性是封装的典型体现。它允许你在 get/set 中加入验证逻辑、懒加载、通知机制（如 WPF 的 INotifyPropertyChanged），而公共字段无法做到这些。此外，属性在二进制兼容性上更好（可以将字段改为属性而不破坏引用它的程序集）。
  2. 接口（Interface）体现了封装还是抽象？
    • 考点：主要体现抽象。接口定义了“做什么”，完全隐藏了“怎么做”。但接口本身也涉及封装的思想，因为它限制了实现类必须遵循的契约。
  3. 如果我把所有字段都设为 public，还算面向对象吗？
    • 考点： technically 算，但是是糟糕的面向对象设计。这破坏了封装性，导致耦合度极高，任何地方都能修改对象状态，使得代码难以维护和调试。这通常被称为“贫血模型”或仅仅是“数据结构”。
  4. C# 9 引入的 record 类型是如何处理封装的？
    • 考点：record 默认生成不可变（Immutable）的属性。它通过编译器生成的 init-only 属性来实现封装，确保对象创建后状态不能被修改，从而在多线程和数据传输场景下提供更强的安全性。

八、什么是LINQ

✅面试简答（考场口述答案）

LINQ (Language Integrated Query) 是 C# 3.0 引入的一项技术，它将查询功能直接集成到编程语言中。

  • 核心作用：允许开发者使用统一的语法（类似 SQL）对不同的数据源（如内存集合、数据库、XML、JSON）进行查询和操作。
  • 主要优势：
    1. 统一性：无论数据源是 List<T> 还是 SQL Server，查询语法基本一致。
    2. 类型安全：查询在编译时检查，避免了字符串拼接 SQL 带来的运行时错误和注入风险。
    3. 简洁性：通过声明式编程减少了大量的 foreach 循环和临时变量。
  • 两种写法：查询语法（Query Syntax，像 SQL）和方法语法（Method Syntax，链式调用扩展方法）。

📚深入解析

1. LINQ 的架构体系

LINQ 不是一个单一的工具，而是一组技术的统称：

技术名称 全称 数据源 特点
LINQ to Objects - 内存中的集合 (IEnumerable<T>) 最基础，直接在 CPU 上执行过滤、排序。
LINQ to Entities EF Core / EF6 关系型数据库 重点。将 LINQ 表达式树转换为 SQL 语句，在数据库端执行。
LINQ to XML XLINQ XML 文档 用于解析和创建 XML。

2. 两种语法对比

假设我们要从用户列表中找出所有年龄大于 18 的用户姓名：

A. 查询语法 (Query Syntax)

  • 看起来像 SQL，适合复杂的多表连接（Join）和分组（Group By）。
var names = from u in users
            where u.Age > 18
            select u.Name;

B. 方法语法 (Method Syntax)

  • 基于 Lambda 表达式和扩展方法，更灵活，支持所有 LINQ 操作符（有些操作符如 Count() 没有查询语法对应物）。
var names = users.Where(u => u.Age > 18)
                 .Select(u => u.Name);
  • 底层真相：编译器最终会将“查询语法”编译成“方法语法”。

3. 核心考点：延迟执行 (Deferred Execution)

这是 LINQ 面试中最常问的原理。

  • 概念：大多数 LINQ 操作符（如 Where, Select, OrderBy）在定义查询时不会立即执行，而是返回一个 IEnumerable<T> 对象。只有当你真正遍历结果（如使用 foreach）或调用即时执行方法（如 ToList(), Count(), First()）时，查询才会真正运行。
  • 优点：可以组合多个查询条件而不产生中间集合，节省内存；支持无限序列。
  • 陷阱：如果多次遍历同一个未缓存的 LINQ 查询，它会重复执行多次。如果数据源在两次遍历之间发生了变化，结果也会不同。
// 此时并未执行数据库查询或内存过滤
var query = users.Where(u => u.Age > 18); 

// 第一次遍历：执行查询
foreach (var user in query) { ... }

// 第二次遍历：再次执行查询！
var list = query.ToList();

4. LINQ to Entities (EF Core) 的特殊性

在后端开发中，LINQ 通常与 EF Core 配合使用。

  • 表达式树 (Expression Tree)：EF Core 接收的不是委托（Delegate），而是表达式树。它会将表达式树解析并翻译成 SQL 语句发送给数据库。
  • 客户端评估 vs 服务端评估：
    • 服务端：Where, Select, Join 等能转成 SQL 的操作会在数据库执行。
    • 客户端：如果使用了 C# 特有的、无法转成 SQL 的方法（如自定义 C# 方法），EF Core 可能会将整个数据集加载到内存后再处理（性能灾难），或者在较新版本中直接报错。

💡面试延伸追问（预判面试官后续提问）

  1. IEnumerable<T> 和 IQueryable<T> 有什么区别？
    • 考点：
      • IEnumerable<T>：针对内存集合，使用委托（Delegate），查询在**客户端（内存）**执行。
      • IQueryable<T>：针对远程数据源（如数据库），使用表达式树（Expression Tree），查询在**服务端（数据库）**执行。
      • 陷阱：如果在 IQueryable 上误用了只能由 IEnumerable 处理的方法，会导致全表加载。
  2. 什么是延迟执行？如何强制立即执行？
    • 考点：延迟执行指定义查询时不运行。调用 ToList(), ToArray(), ToDictionary(), Count(), Any() 等会触发立即执行。
  3. LINQ 中的 Select 和 SelectMany 有什么区别？
    • 考点：Select 是一对一映射；SelectMany 是一对多映射（扁平化），常用于处理嵌套集合（如获取所有订单下的所有商品明细）。
  4. 在高性能场景下，使用 LINQ 有什么需要注意的性能问题？
    • 考点：
      • 避免在循环中执行 LINQ 查询。
      • 注意闭包捕获变量导致的意外行为。
      • 在 EF Core 中，警惕“N+1”问题（虽然在 EF Core 中更多是导航属性加载问题，但 LINQ 写法不当也会导致多次查询）。
      • 大量数据时使用 AsNoTracking() 提高查询性能。

九、什么是扩展方法

✅面试简答（考场口述答案）

扩展方法（Extension Methods）是 C# 3.0 引入的一种特性，允许开发者在不修改原始类源码、不继承该类的情况下，为现有类型“添加”新方法。

  • 本质：它实际上是静态类中的静态方法，只是通过编译器语法糖，让调用者可以像调用实例方法一样使用它。
  • 定义要求：
    1. 必须定义在静态类中。
    2. 必须是静态方法。
    3. 第一个参数必须带有 this 修饰符，且类型指定了要扩展的目标类型。
  • 典型应用：LINQ 的所有操作符（如 Where, Select, OrderBy）本质上都是对 IEnumerable<T> 的扩展方法。

📚深入解析

1. 代码实现示例

假设我们要为 string 类型增加一个判断是否为空或空白的方法：

// 1. 必须是一个静态类
public static class StringExtensions
{
    // 2. 必须是静态方法
    // 3. 第一个参数带 this，表示扩展 string 类型
    public static bool IsNullOrWhiteSpace(this string str)
    {
        return string.IsNullOrWhiteSpace(str);
    }
    
    // 扩展其他类型，如 int
    public static bool IsEven(this int number)
    {
        return number % 2 == 0;
    }
}

// 调用方式：看起来像实例方法
string name = null;
bool result = name.IsNullOrWhiteSpace(); // 输出: true

int num = 4;
bool isEven = num.IsEven(); // 输出: true

2. 编译原理（底层真相）

当你写 name.IsNullOrWhiteSpace() 时，C# 编译器（Roslyn）会在后台将其转换为普通的静态方法调用： StringExtensions.IsNullOrWhiteSpace(name)

这意味着：

  • 没有真正的多态：扩展方法是静态绑定的。如果变量声明类型是基类，即使运行时指向子类，调用的也是基类的扩展方法（如果有的话）。
  • 性能无损耗：因为它就是普通的方法调用，没有反射，没有额外的对象分配。

3. 优先级规则（高频考点）

如果一个类型既有实例方法，又有同名的扩展方法，编译器会优先选择实例方法。

public class MyClass
{
    public void Show() { Console.WriteLine("Instance Method"); }
}

public static class MyExtensions
{
    public static void Show(this MyClass obj) { Console.WriteLine("Extension Method"); }
}

// 测试
MyClass obj = new MyClass();
obj.Show(); // 输出: "Instance Method" (实例方法优先级更高)

4. 扩展接口的强大之处

你可以为接口定义扩展方法，所有实现该接口的类都会自动获得这个方法。这是 LINQ 能够统一操作 List<T>, Array, HashSet<T> 的原因（因为它们都实现了 IEnumerable<T>）。

public static class EnumerableExtensions
{
    // 所有实现了 IEnumerable<T> 的集合都能用这个方法
    public static void PrintAll<T>(this IEnumerable<T> source)
    {
        foreach (var item in source)
        {
            Console.WriteLine(item);
        }
    }
}

5. 注意事项与最佳实践

  • 命名空间依赖：调用扩展方法前，必须 using 包含该扩展方法所在静态类的命名空间。否则编译器找不到该方法。
  • 不要滥用：
    • 如果你能修改源码，优先使用实例方法。
    • 如果需要多态行为（虚方法），请使用继承或接口，不要用扩展方法。
    • 扩展方法只能访问目标类型的公共成员（Public），无法访问私有或受保护成员。
  • IntelliSense 标识：在 Visual Studio 中，扩展方法在智能提示列表中会有一个特殊的向下箭头图标，以示区别。

💡面试延伸追问（预判面试官后续提问）

  1. 扩展方法可以实现多态吗？
    • 考点：不能。扩展方法是静态绑定的（编译时确定）。如果有一个基类扩展方法和一个子类扩展方法，调用哪个取决于变量的声明类型，而不是运行时对象的实际类型。
  2. 为什么 LINQ 的方法都是扩展方法而不是直接写在 List 类里？
    • 考点：解耦与通用性。List<T> 只是众多集合的一种。通过将方法扩展在 IEnumerable<T> 接口上，LINQ 可以一次性支持数组、链表、字典、自定义集合等所有可枚举类型，无需修改任何集合类的源码。
  3. 如果两个不同的命名空间下定义了签名完全相同的扩展方法，会发生什么？
    • 考点：编译错误（CS0121）。编译器无法确定该调用哪一个。解决方法是：只 using 其中一个命名空间，或者直接使用静态方法语法调用（Namespace.Class.Method(obj)）来明确指定。
  4. 扩展方法可以是泛型的吗？
    • 考点：可以。例如 public static T FirstOrDefault<T>(this IEnumerable<T> source)。这使得扩展方法具有极强的通用性。

十、什么是IEnumerable

✅面试简答（考场口述答案）

IEnumerable<T> 是 .NET 中用于表示“可枚举集合”的核心接口。

  • 核心作用：它允许使用 foreach 循环遍历集合，也是 LINQ 查询的基础。
  • 关键特性：
    1. 只读性：它只提供读取数据的能力，不支持添加、删除或修改元素。
    2. 延迟执行（Lazy Evaluation）：这是最重要的考点。IEnumerable 的查询通常不会立即执行，只有在真正遍历（如调用 MoveNext()）时才会逐个获取数据。
    3. 单向遍历：只能从头到尾依次访问，不能随机访问（如通过索引 list[0]）。
  • 底层机制：它依赖于 迭代器模式，通过 GetEnumerator() 方法返回一个 IEnumerator 对象来维护遍历状态。

📚深入解析

1. 接口定义与继承关系 

// 简化版定义
public interface IEnumerable<out T> : IEnumerable
{
    IEnumerator<T> GetEnumerator();
}
  • 协变性 (out T)：IEnumerable<out T> 支持协变。这意味着如果 Dog 继承自 Animal，那么 IEnumerable<Dog> 可以隐式转换为 IEnumerable<Animal>。这提高了代码的复用性。

2. 核心工作原理：迭代器模式

当你写 foreach (var item in collection) 时，编译器实际上将其转换为类似以下的逻辑：

IEnumerator<int> enumerator = collection.GetEnumerator();
try
{
    while (enumerator.MoveNext()) // 移动到下一个元素，返回是否有更多元素
    {
        int item = enumerator.Current; // 获取当前元素的值
        Console.WriteLine(item);
    }
}
finally
{
    enumerator.Dispose(); // 确保资源释放
}
  • MoveNext()：推动指针前进，并返回 bool 判断是否结束。
  • Current：获取当前位置的值。

3. 延迟执行（Deferred Execution）详解

这是 IEnumerable 与 List 最大的区别。

// 假设 db.Users 是一个 IQueryable/IEnumerable 数据源
var query = db.Users.Where(u => u.Age > 18); // 此时并未查询数据库！

// 只有当这里开始遍历时，Where 里的逻辑才会真正执行
foreach (var user in query) 
{
    Console.WriteLine(user.Name);
}
  • 优势：节省内存。如果数据源有 100 万条数据，但你只需要前 10 条，IEnumerable 可以在取到第 10 条后就停止后续数据的加载和处理。
  • 陷阱：如果你多次遍历同一个 IEnumerable 变量，它会重新执行整个查询逻辑。如果数据源在两次遍历之间发生了变化，结果会不一致。

4. IEnumerable vs IQueryable vs List

特性 IEnumerable<T> IQueryable<T> List<T>
执行位置 客户端（内存） 服务端（数据库） 内存
过滤时机 加载所有数据后在内存过滤 生成 SQL，在数据库过滤 加载所有数据后在内存过滤
适用场景 LINQ to Objects, 小数据集 LINQ to Entities (EF Core), 大数据集 需要随机访问、增删改
延迟执行 支持 支持 不支持（立即加载）

5. 常见面试题：yield return

yield return 是实现 IEnumerable 最优雅的方式。它让编译器自动生成状态机来实现迭代器。

public static IEnumerable<int> GetNumbers()
{
    for (int i = 0; i < 10; i++)
    {
        Console.WriteLine($"Yielding {i}");
        yield return i; // 每次调用 MoveNext 时执行到这里暂停
    }
}

💡面试延伸追问（预判面试官后续提问）

  1. IEnumerable 和 ICollection / IList 有什么区别？
    • 考点：IEnumerable 是最基础的，只支持遍历；ICollection 增加了 Count 属性和同步方法；IList 进一步增加了索引访问（this[int index]）和增删改能力。性能上，IList 支持随机访问，效率更高。
  2. 为什么在 EF Core 中，先调用 ToList() 再调用 Where 会导致性能问题？
    • 考点：ToList() 会触发立即执行，将数据库中的所有数据加载到内存中变成 List（即 IEnumerable）。随后的 Where 变成了 LINQ to Objects，在内存中过滤。如果表有百万级数据，这会耗尽内存并拖慢速度。正确的做法是保持 IQueryable 直到最后再 ToList()。
  3. 如何手动实现一个自定义的 IEnumerable？
    • 考点：可以实现 IEnumerable<T> 接口并返回一个自定义的 IEnumerator，或者更简单地，使用 yield return 语法。
  4. IEnumerable 是线程安全的吗？
    • 考点：不是。标准的 IEnumerable 实现（如 List<T> 的枚举器）在遍历过程中如果集合被修改（Add/Remove），会抛出 InvalidOperationException。如果需要线程安全，需使用 ConcurrentBag 等并发集合或在遍历期间加锁。

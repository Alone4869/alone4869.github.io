1、值类型与引用类型

1.1 值类型和引用类型的区别？

值类型包括简单类型、结构体类型和枚举类型，引用类型包括自定义类、数组、接口、委托等。

  1. 赋值方式：将一个值类型变量赋给另一个值类型变量时，将复制包含的值。这与引用类型变量的赋值不同，引用类型变量的赋值只复制对象的引用（即内存地址，类似 C++ 中的指针），而不复制对象本身。
  2. 继承：值类型不可能派生出新的类型，所有的值类型均隐式派生自 System.ValueType。但与引用类型相同的是，结构也可以实现接口。
  3. null：与引用类型不同，值类型不可能包含 null 值。然而，可空类型功能允许将 null 赋给值类型。
  4. 默认值：每种值类型均有一个隐式的默认构造函数来初始化该类型的默认值，值类型初始会默认为 0，引用类型默认为 null。
  5. 存储位置：值类型存储在栈中，引用类型存储在托管堆中。

【补充】 “值类型在栈上、引用类型在堆上"是简化说法，更准确的描述：值类型的局部变量通常分配在栈上，但作为引用类型字段的值类型会随对象一起在堆上（见 1.5）；ref struct 则强制只能存在于栈上。

1.2 结构和类的区别？

结构体是值类型，类是引用类型，主要区别如题 1.1。

其他的区别：

  • 结构不支持无参构造函数（指自定义的无参构造函数，C# 10+ 已放开此限制），不支持析构函数，并且不能有 protected 修饰；
  • 结构常用于数据存储，类 class 多用于行为；
  • class 需要用 new 关键字实例化对象，struct 可以不使用 new 关键字；
  • class 可以为抽象类，struct 不支持抽象。

【补充】 C# 10 起结构体也可以声明显式无参构造函数和字段初始值；结构体可声明 readonly/ref struct。选择原则：数据小、不可变、短生命周期用 struct；需要多态、继承、引用语义用 class。

1.3 delegate 是引用类型还是值类型？enum、int[] 和 string 呢？

enum 枚举是值类型，其他都是引用类型。

1.4 堆和栈的区别？

线程堆栈（简称栈 Stack）与托管堆（简称堆 Heap）：

  • 值类型大多分配在栈上，引用类型都分配在堆上；
  • 栈由操作系统管理，栈上的变量在其作用域完成后就被释放，效率较高，但空间有限；堆受 CLR 的 GC 控制；
  • 栈是基于线程的，每个线程都有自己的线程栈，初始大小为 1M；堆是基于进程的，一个进程分配一个堆，堆的大小由 GC 根据运行情况动态控制。

1.5 “结构"对象可能分配在堆上吗？什么情况下会发生，有什么需要注意的吗？

结构是值类型，有两种情况会分配在堆上：结构作为 class 的一个字段或属性，会随 class 一起分配在堆上面；装箱后会在堆中存储。应尽量避免值类型的装箱，值类型的拆箱和装箱都有性能损失（见下一节）。

1.6 理解参数按值传递？以及按引用传递？

  • 按值传递：对于值类型传递的是它的值拷贝副本，而引用类型传递的是引用变量的内存地址，它们还是指向的同一个对象。
  • 按引用传递：通过关键字 out 和 ref 传递参数的内存地址，值类型和引用类型的效果是相同的。

1.7 out 和 ref 的区别与相同点？

out 和 ref 都指示编译器传递参数地址，在行为上是相同的；使用机制稍有不同：ref 要求参数在使用之前要显式初始化，out 要在方法内部初始化。out 和 ref 不可以重载，即不能定义 Method(ref int a) 和 Method(out int a) 这样的重载——从编译角度看，二者的实质是相同的，只是使用时有区别。

1.8 有几种方法可以判定值类型和引用类型？

简单来说，继承自 System.ValueType 的是值类型，反之是引用类型。

1.9 C# 支持哪几个预定义的值类型？C# 支持哪些预定义的引用类型？

值类型：整数、浮点数、字符、bool 和 decimal；引用类型：Object、String。

【补充】 完整清单：

  • 预定义值类型：sbyte、byte、short、ushort、int、uint、long、ulong、char、float、double、decimal、bool（以及 dynamic 在运行时表现为 object 引用类型）；
  • 预定义引用类型：object、string、dynamic。

1.10 说说值类型和引用类型的生命周期？

值类型在作用域结束后释放。引用类型由 GC 垃圾回收器回收。

【补充】 更准确的描述：值类型（局部变量）在离开其作用域时出栈释放；引用类型对象在托管堆上分配，当不再被任何根（Root）引用时，由 GC 在不确定的时间回收（见第 6 节 GC 部分）。作为字段时，两者的生命周期都跟随所属对象。

1.11 如果结构体中定义引用类型，对象在内存中是如何存储的？

例如下面结构体中的 class 类 User 对象是存储在栈上，还是堆上？

public struct MyStruct
{
    public int Index;
    public User User;
}

MyStruct 存储在栈中，其字段 User 的实例存储在堆中，MyStruct.User 字段存储指向 User 对象的内存地址。

2、装箱与拆箱

2.1 什么是拆箱和装箱？

装箱就是值类型转换为引用类型，拆箱就是引用类型（被装箱的对象）转换为值类型。

int x = 1023;
object o = x;   // 装箱：值类型 → 引用类型
int y = (int)o; // 拆箱：引用类型 → 值类型

2.2 什么是箱子？

就是引用类型对象。

2.3 箱子放在哪里？

托管堆上。

2.4 装箱和拆箱有什么性能影响？

装箱和拆箱都涉及到内存的分配和对象的创建，有较大的性能影响。

【补充】 装箱会产生一次堆内存分配（对象 + 类型指针 + 同步索引块），拆箱有一次类型检查与拷贝；高频代码路径上应避免。可用 IL（box/unbox 指令）佐证。

2.5 如何避免隐式装箱？

编码中，多使用泛型、显式装箱。

【补充】 典型隐式装箱场景与规避：

int x = 1;
object o = x;                    // 显式装箱（可接受）
string s = string.Format("{0}", x); // 隐式装箱 → 用 $"{x}" 插值
ArrayList list = new ArrayList();
list.Add(x);                     // 隐式装箱 → 改用 List<int>
  • 使用泛型集合（List<T>、Dictionary<K,V>）替代非泛型集合（ArrayList、Hashtable）；
  • 字符串拼接优先用 $"" 插值或 StringBuilder；
  • 避免把值类型当作 object/接口类型传递（接口调用也会触发装箱）。

2.6 箱子的基本结构？

箱子就是一个引用类型对象，它的结构主要包含两部分：值类型字段值；引用类型的标准配置——引用对象的额外空间：TypeHandle 和同步索引块。

2.7 装箱的过程？

  1. 在堆中申请内存，内存大小为值类型的大小，再加上额外固定空间（引用类型的标配：TypeHandle 和同步索引块）；
  2. 将值类型的字段值（x=1023）拷贝到新分配的内存中；
  3. 返回新引用对象的地址（给引用变量 object o）。

2.8 拆箱的过程？

  1. 检查实例对象（object o）是否有效，如是否为 null，其装箱的类型与拆箱的类型（int）是否一致，如检测不合法，抛出异常（InvalidCastException）；
  2. 指针返回，即获取装箱对象（object o）中值类型字段值的地址；
  3. 字段拷贝，把装箱对象（object o）中值类型字段值拷贝到栈上，即创建一个新的值类型变量来存储拆箱后的值。

3、string 与字符串操作

3.1 字符串是引用类型还是值类型？

引用类型。

【补充】 但 string 具有"值语义”：==/Equals 比较的是内容而非引用；string 不可变（immutable），所有修改操作都会产生新对象。

3.2 在字符串连加处理中，最好采用什么方式，理由是什么？

少量字符串连接，使用 String.Concat；大量字符串使用 StringBuilder，因为 StringBuilder 的性能更好，如果使用 string 的话会创建大量字符串对象。

3.3 使用 StringBuilder 时，需要注意些什么问题？

  • 少量字符串时，尽量不要用，StringBuilder 本身是有一定性能开销的；
  • 大量字符串连接使用 StringBuilder 时，应该设置一个合适的容量（Capacity），避免频繁扩容。

【补充】

var sb = new StringBuilder(1024); // 预估容量，减少扩容
for (int i = 0; i < 10000; i++) sb.Append(i).Append(',');
string result = sb.ToString();

此外可了解字符串驻留池（Intern Pool）：相同内容的字符串字面量在 CLR 中只存一份；string.Intern() 可主动驻留，但一般不推荐滥用（占用内存）。

4、类与接口

4.1 所有类型都继承 System.Object 吗？

基本上是的，所有值类型和引用类型都继承自 System.Object；接口是一个特殊的类型，不继承自 System.Object。

【补充】 值类型通过 System.ValueType → System.Object 间接继承；接口类型在 C# 中不声明基类（不继承任何类），但任何实现接口的类型都可以赋给 object。

4.2 解释 virtual、sealed、override 和 abstract 的区别

  • virtual：声明虚方法的关键字，说明该方法可以被重写；
  • sealed：说明该类不可被继承（也可修饰成员，阻止进一步重写）；
  • override：重写基类的方法；
  • abstract：声明抽象类和抽象方法的关键字，抽象方法不提供实现，由子类实现，抽象类不可实例化。

【补充】 修饰符组合规则：abstract 与 virtual 不能同时使用；override 不能与 new、static 同时使用；抽象成员只能在抽象类中声明；sealed override 表示"重写后不再允许下级重写”。

4.3 接口和类有什么异同？

不同点：

  1. 接口不能直接实例化；
  2. 接口只包含方法或属性的声明，不包含方法的实现；
  3. 接口可以多继承，类只能单继承；
  4. 类有分部类的概念，定义可在不同的源文件之间进行拆分，接口同样支持分部（partial interface）；
  5. 表达的含义不同：接口主要定义一种规范，统一调用方法，即规范类、约束类；类是方法功能的实现和集合。

相同点：

  1. 接口、类和结构都可以从多个接口继承；
  2. 接口类似于抽象基类：继承接口的任何非抽象类型都必须实现接口的所有成员；
  3. 接口和类都可以包含事件、索引器、方法和属性。

4.4 抽象类和接口有什么区别？

  1. 继承：接口支持多继承；抽象类不能实现多继承。
  2. 表达的概念：接口用于规范，更强调契约；抽象类用于共性，强调父子。抽象类是一类事物的高度聚合，继承抽象类的子类与抽象类是"Is A"的关系；接口定义行为规范，强调"Can Do"的关系。
  3. 方法实现：抽象类中的方法可以给出实现，也可以不给出；接口的方法（抽象规则）都不能给出实现，接口中方法不能加修饰符（C# 8+ 接口默认实现除外）。
  4. 子类重写：继承类对抽象类的抽象方法可以不用重写（可延用抽象类的方法实现）；对接口定义的方法或属性，继承类必须给出实现。
  5. 新增方法的影响：在抽象类中新增方法，继承类可以不用作任何处理；接口新增成员则所有实现类都要相应修改（C# 8+ 默认接口实现可缓解）。
  6. 适用范围：接口可以作用于值类型（枚举可以实现接口）和引用类型；抽象类只能作用于引用类型。
  7. 成员限制：接口不能包含字段和已实现的方法，只包含方法、属性、索引器、事件的签名；抽象类可以定义字段、属性、包含有实现的方法。

【补充】 C# 8+ 引入了默认接口方法（DIM），接口成员可以带默认实现，但设计上仍推荐接口保持"纯契约"。

4.5 重载与覆盖的区别？

重载（Overload）：当类包含两个名称相同但签名不同（方法名相同、参数列表不相同）的方法时发生。用方法重载来提供在语义上完成相同而功能不同的方法。

覆盖/重写（Override）：在类的继承中使用，通过重写子类方法可以改变父类虚方法的实现。

主要区别：

  1. 方法的覆盖是子类和父类之间的关系，是垂直关系；方法的重载是同一个类中方法之间的关系，是水平关系；
  2. 覆盖只能由一个方法（或只能由一对方法）产生关系；方法的重载是多个方法之间的关系；
  3. 覆盖要求参数列表相同；重载要求参数列表不同；
  4. 覆盖关系中，调用哪个方法体根据对象的类型来决定；重载关系根据调用时的实参表与形参表来选择方法体。

4.6 在继承中 new 和 override 相同点和区别？ 

static void Main(string[] args)
{
    B1 b1 = new B1(); B2 b2 = new B2();
    b1.Print(); b2.Print();      // 输出 B1、B2
    A ab1 = new B1(); A ab2 = new B2();
    ab1.Print(); ab2.Print();   // 输出 B1、A
    Console.ReadLine();
}
public class A
{
    public virtual void Print() { Console.WriteLine("A"); }
}
public class B1 : A
{
    public override void Print() { Console.WriteLine("B1"); }
}
public class B2 : A
{
    public new void Print() { Console.WriteLine("B2"); }
}

【补充】结果解释

  • b1.Print()、b2.Print() 通过派生类引用调用，都调用派生类自己的方法，输出 B1、B2；
  • ab1.Print()：B1 用 override 重写了虚方法，通过基类引用调用时发生多态分发，输出 B1；
  • ab2.Print()：B2 用 new 隐藏了基类方法，通过基类引用调用时按**静态类型（A）**解析，输出 A。

即：override 参与多态（动态绑定），new 只是隐藏（编译期绑定到声明的类型）。

4.7 class 中定义的静态字段是存储在内存中的哪个地方？为什么会说它不会被 GC 回收？

随类型对象存储在内存的加载堆（Loader Heap）上，因为加载堆不受 GC 管理，其生命周期随 AppDomain，不会被 GC 回收。

【补充】 这是 CLR 内部实现概念：每个类型都有对应的"类型对象"，静态字段作为类型对象的一部分存放于加载堆。卸载 AppDomain（或进程退出）时才会释放，因此滥用静态集合容易造成"内存泄露"（见 6.8）。

5、常量、字段、属性、特性与委托

5.1 const 和 readonly 有什么区别？

const 关键字用来声明编译时常量，readonly 用来声明运行时常量。主要区别：

  1. 初始化位置不同：const 必须在声明的同时赋值；readonly 既可以在声明处赋值，也可以在构造方法里赋值；
  2. 修饰对象不同：const 既可以修饰类的字段，也可以修饰局部变量；readonly 只能修饰类的字段；
  3. 确定时机不同：const 是编译时常量，在编译时确定该值，且值在编译时被内联到代码中；readonly 是运行时常量，在运行时确定该值；
  4. 静态性：const 默认是静态的；readonly 如果设置成静态需要显式声明（static readonly）；
  5. 支持的类型不同：const 只能修饰基元类型或值为 null 的其他引用类型；readonly 可以是任何类型。
public class Program
{
    public readonly int PORT;
    static void Main(string[] args)
    {
        B a = new B();
        Console.WriteLine(a.PORT);
        Console.WriteLine(B.PORT2);
        Console.WriteLine(a.PORT3.ccc);
        Console.ReadLine();
    }
}
class B
{
    // readonly 既可以在声明处赋值，也可以在构造方法里赋值
    public readonly int PORT;
    // const 必须在声明的同时赋值
    public const int PORT2 = 10;
    // 错误：public const A PORT3 = new A();  const 只能修饰基元类型或值为 null 的其他引用类型
    // readonly 可以是任何类型
    public readonly A PORT3 = new A();
    public B()
    {
        PORT = 11;
    }
}
class A
{
    public string ccc = "aaaa";
}

5.2 字段与属性有什么异同？

  • 属性提供了更为强大的、灵活的功能来操作字段；
  • 出于面向对象的封装性，字段一般不设计为 public；
  • 属性允许在 set 和 get 中编写代码；
  • 属性允许控制 set 和 get 的可访问性，从而提供只读或可读写的功能（逻辑上只写没有意义）；
  • 属性可以使用 override 和 new。

【补充】 自动属性 public string Name { get; set; } 编译后仍会生成私有字段；{ get; private set; } 可控制写权限；属性可以被绑定（WPF 数据绑定要求属性而非字段）。

5.3 静态成员和非静态成员的区别？

  • 静态变量使用 static 修饰符进行声明，静态成员在加载类的时候就被加载（静态字段随类型对象存放在 Load Heap 上），通过类进行访问；
  • 不带有 static 修饰符声明的变量称做非静态变量，在对象被实例化时创建，通过对象进行访问；
  • 一个类的所有实例的同一静态变量都是同一个值；同一个类的不同实例的同一非静态变量可以是不同的值；
  • 静态函数（静态方法）的实现里不能使用非静态成员，如非静态变量、非静态函数等。

5.4 特性是什么？如何使用？

特性（Attribute）与属性是完全不相同的两个概念，只是在名称上比较相近。Attribute 就是关联了一个目标对象的一段配置信息，本质上是一个类，其为目标元素提供关联附加信息，这段附加信息存储在 dll 内的元数据。它本身没什么意义，运行时以反射的方式来获取附加信息。

【补充】

[Obsolete("请使用新方法")]
public void OldMethod() { }

[Serializable]
public class MyClass { }

自定义特性：继承 System.Attribute，用 [AttributeUsage] 限定使用范围，运行时用 GetCustomAttribute<T>() 读取。

5.5 C# 中的委托是什么？事件是不是一种委托？

简单来说，委托类似于 C 或 C++ 中的函数指针，允许将方法作为参数进行传递。

  • C# 中的委托都继承自 System.Delegate 类型；
  • 委托类型的声明与方法签名类似，有返回值和参数；
  • 委托是一种可以封装命名（或匿名）方法的引用类型，把方法当做指针传递，但委托是面向对象、类型安全的。

事件可以理解为一种特殊的委托，事件内部是基于委托来实现的。

【补充】 事件与委托的关键区别：事件只能通过 +=/-= 订阅（外部不能直接调用/赋值），且只能在声明它的类内部触发（Invoke）；委托可以在外部赋值和调用。事件常用于观察者模式。

6、GC 与内存管理

原文该节编号不连续（缺失 35），已统一重排为 110。

6.1 简述一下一个引用对象的生命周期？

  1. new 创建对象并分配内存；
  2. 对象初始化（构造函数）；
  3. 对象操作、使用；
  4. 资源清理（非托管资源，Dispose）；
  5. GC 垃圾回收。

6.2 GC 进行垃圾回收时的主要流程是？

  1. 标记（Mark）：先假设所有对象都是垃圾，根据应用程序根（Root）遍历堆上的每一个引用对象，生成可达对象图，对还在使用的对象（可达对象）进行标记（在对象同步索引块中开启一个标示位）；
  2. 清除（Sweep）：针对所有不可达对象进行清除操作；普通对象直接回收内存，实现了终结器（析构函数）的对象需要单独回收处理。清除之后内存变得不连续，进入第 3 步；
  3. 压缩（Compact）：把剩下的对象转移到一个连续的内存区域，因为这些对象地址变了，还需要把那些 Root 引用的指针地址修改为移动后的新地址。

【补充】 GC 采用分代回收：0 代（新分配的对象）、1 代、2 代（长期存活）；年轻代回收频繁、开销小，老年代回收少、开销大。大对象（≥85KB）分配在大对象堆（LOH），默认不压缩。GC 有工作站模式与服务器模式（gcServer），可在运行时配置。

6.3 GC 在哪些情况下会进行回收工作？

  • 内存不足溢出时（0 代对象充满时）；
  • Windows 报告内存不足时，CLR 会强制执行垃圾回收；
  • CLR 卸载 AppDomain，GC 回收所有；
  • 调用 GC.Collect；
  • 其他情况，如主机拒绝分配内存、物理内存不足、超出短期存活代的存段门限。

【补充】 正常情况下不要主动调用 GC.Collect()，会打乱 GC 的分代策略、降低性能；仅在某些测试/诊断场景使用。

6.4 using() 语法是如何确保对象资源被释放的？如果内部出现异常依然会释放资源吗？

using() 只是一种语法形式，其本质还是 try…finally 的结构，可以保证 Dispose 始终会被执行——即使内部抛出异常，finally 中的 Dispose() 也会执行。

6.5 解释一下 C# 里的析构函数？为什么有些编程建议里不推荐使用析构函数呢？

C# 里的析构函数其实就是终结器（Finalizer），只是长得像 C++ 里的析构函数而已。

不推荐使用析构函数的原因：第一，Finalize 本身性能并不好；其次，很多人搞不清楚 Finalize 的原理，可能会滥用，导致内存泄露，因此干脆别用。

6.6 Finalize() 和 Dispose() 之间的区别？

Finalize() 和 Dispose() 都是 .NET 中提供释放非托管资源的方式，主要区别在于执行者和执行时间不同：

  • Finalize 由垃圾回收器调用；Dispose 由对象调用；
  • Finalize 无需担心因为没有调用 Finalize 而使非托管资源得不到释放；Dispose 必须手动调用；
  • Finalize 不能保证立即释放非托管资源，Finalizer 被执行的时间是在对象不再被引用后的某个不确定的时间；Dispose 一调用便释放非托管资源；
  • 只有 class 类型才能重写 Finalize，而结构不能；类和结构都能实现 IDisposable。

另外一个重点区别：终结器会导致对象复活一次，即会被 GC 回收两次才最终完成回收工作（第一次进入终结队列、第二次才真正释放），这也是有些人不建议开发人员使用终结器的主要原因。

【补充】 正确模式是 Dispose 模式：实现 IDisposable，在 Dispose 中释放非托管资源并调用 GC.SuppressFinalize(this)，避免对象进入终结队列；终结器只作为兜底。

6.7 Dispose 和 Finalize 方法在何时被调用？

  • Dispose：一调用便释放非托管资源；
  • Finalize：不能保证立即释放非托管资源，Finalizer 被执行的时间是在对象不再被引用后的某个不确定的时间（由 GC 决定）。

6.8 .NET 中的托管堆中是否可能出现内存泄露的现象？

是的，可能会。比如：

  • 不正确的使用静态字段，导致大量数据无法被 GC 释放；
  • 没有正确执行 Dispose()，非托管资源没有得到释放；
  • 不正确的使用终结器 Finalize()，导致无法正常释放资源；
  • 其他不正确的引用（如事件订阅未取消、委托持有长生命周期对象），导致大量托管对象无法被 GC 释放。

6.9 在托管堆上创建新对象有哪几种常见方式？

  • new 一个对象；
  • 字符串赋值，如 string s1 = "abc"；
  • 值类型装箱。

【补充】 反射创建（Activator.CreateInstance）、对象克隆、LINQ 产生的新对象等也都会在堆上分配。

7、多线程编程与线程同步

7.1 描述线程与进程的区别？

  • 一个应用程序实例是一个进程，一个进程内包含一个或多个线程，线程是进程的一部分；
  • 进程之间是相互独立的，它们有各自的私有内存空间和资源；进程内的线程可以共享其所属进程的所有资源。

7.2 lock 为什么要锁定一个参数，可不可以锁定一个值类型？这个参数有什么要求？

lock 的锁对象要求为一个引用类型。可以锁定值类型，但值类型会被装箱，每次装箱后的对象都不一样，会导致锁定无效。

对于 lock 锁，锁定的这个对象参数才是关键，这个参数的同步索引块指针会指向一个真正的锁（同步块），这个锁（同步块）会被复用。

【补充】 最佳实践：

  • 使用 private static readonly object _locker = new object(); 作为专用锁对象；
  • 不要用 lock(this)、lock(typeof(Class))（易被外部访问导致死锁）；
  • 不要用 string 作为锁对象（字符串驻留可能被意外共享）；
  • 锁代码块尽量小、不跨方法，避免在持锁时执行耗时/阻塞操作。

7.3 多线程和异步有什么关系和区别？

多线程是实现异步的主要方式之一，异步并不等同于多线程。实现异步的方式还有很多，比如利用硬件的特性（IO 完成端口）、使用进程或纤程等。在 .NET 中就有很多的异步编程支持，比如很多地方都有 Begin**、End** 的方法，就是一种异步编程支持，它内部有些是利用多线程，有些是利用硬件的特性来实现的异步编程。

【补充】 现代 .NET 异步以 Task/async-await（TAP）为主：await 并不一定创建新线程（IO 型异步用硬件/内核机制，CPU 型用线程池）；异步是为了"不阻塞调用线程"，多线程是为了"并行利用多核"。

7.4 线程池的优点有哪些？又有哪些不足？

优点：减小线程创建和销毁的开销，可以复用线程；减少线程上下文切换的性能损失；在 GC 回收时，较少的线程更有利于 GC 的回收效率。

缺点：线程池无法对一个线程有更多的精确控制，如了解其运行状态等；不能设置线程的优先级；加入到线程池的任务（方法）不能有返回值；对于需要长期运行的任务不适合线程池。

【补充】 后两点在 Task 时代已缓解：Task 默认在线程池上执行但可以有返回值（Task<T>）；需要长期运行可指定 TaskCreationOptions.LongRunning。线程池可用 ThreadPool.SetMaxThreads/SetMinThreads 调节。

7.5 Mutex 和 lock 有何不同？一般用哪一个作为锁更好？

Mutex 是一个基于内核模式的互斥锁，支持锁的递归调用；Lock 是一个混合锁（本质是 Monitor）。一般建议使用 lock 更好，因为 lock 的性能更好（内核态/用户态切换开销小）。

【补充】 Mutex 的优势是跨进程同步（如"单实例应用"），进程内同步优先用 lock/Monitor/SemaphoreSlim。

7.6 Thread 与 Task 的区别

Thread 类主要用于实现线程的创建以及执行；Task 类表示以异步方式执行的单个操作。

1、Task 是基于 Thread 的，是比较高层级的封装，Task 最终还是需要 Thread 来执行。

2、Task 默认使用后台线程执行，Thread 默认使用前台线程

static void Main(string[] args)
{
    Thread thread = new Thread(obj => { Thread.Sleep(3000); });
    thread.Start();
}
// 上面代码，主程序在3秒后结束（前台线程会阻止进程退出）

static void Main(string[] args)
{
    Task<int> task = new Task<int>(() =>
    {
        Thread.Sleep(3000);
        return 1;
    });
    task.Start();
}
// 而这段代码，会瞬间结束（后台线程不会阻止进程退出）

3、Task 可以有返回值，Thread 没有返回值（Thread 可通过 Start 方法参数传参，但十分不便）

static void Main(string[] args)
{
    Task task = new Task(LongRunningTask);
    task.Start();
    Console.WriteLine(task.Result);
}
private static int LongRunningTask()
{
    Thread.Sleep(3000);
    return 1;
}

4、Task 可以执行后续操作（ContinueWith），Thread 不能

static void Main(string[] args)
{
    Task task = new Task(LongRunningTask);
    task.Start();
    Task childTask = task.ContinueWith(SquareOfNumber);
    Console.WriteLine("Sqaure of number is :" + childTask.Result);
    Console.WriteLine("The number is :" + task.Result);
}
private static int LongRunningTask()
{
    Thread.Sleep(3000);
    return 2;
}
private static int SquareOfNumber(Task obj)
{
    return obj.Result * obj.Result;
}

5、Task 可取消任务执行，Thread 不行

static void Main(string[] args)
{
    using (var cts = new CancellationTokenSource())
    {
        Task task = new Task(() => { LongRunningTask(cts.Token); });
        task.Start();
        Console.WriteLine("Operation Performing...");
        if (Console.ReadKey().Key == ConsoleKey.C)
        {
            Console.WriteLine("Cancelling..");
            cts.Cancel();
        }
        Console.Read();
    }
}
private static void LongRunningTask(CancellationToken token)
{
    for (int i = 0; i < 10000000; i++)
    {
        if (token.IsCancellationRequested)
        {
            break;
        }
        else
        {
            Console.WriteLine(i);
        }
    }
}

6、异常传播：Thread 在父方法上获取不到异常（未捕获异常直接导致进程终止），而 Task 可以（异常封装在 Task.Exception 中，通过 await/Result 观察）。

【补充】 现代代码推荐直接用 Task.Run(...) 或 async/await，配合 await 等待、ContinueWith 或 await 后续处理、CancellationToken 取消、await 捕获异常。

线程间互相通信

C# 线程间互相通信主要用到两个类：AutoResetEvent 和 ManualResetEvent。

一、AutoResetEvent

AutoResetEvent 允许线程通过发信号互相通信，线程通过调用 AutoResetEvent 上的 WaitOne 来等待信号。如果 AutoResetEvent 为非终止状态，则线程会被阻止，并等待当前控制资源的线程通过调用 Set 来通知资源可用。

类比：吃快餐的时候都会排队付款，收银员发送收款通知，客户依次付钱。

AutoResetEvent 类一次只能通知一个等待的线程，且通知一次过后会立即将 AutoResetEvent 对象的状态置为 false——如果有两个客户都在等待收银员通知，AutoResetEvent 对象的 Set 方法只能通知到第一个客户。

二、ManualResetEvent

在 AutoResetEvent 中，如果要通知两个线程，则 Set 方法要被执行两次。但如果有客户中了彩票，要请部门的 10 个同事吃饭——只要 Set 一次，所有在等待的线程都会解除等待，相当于收银员只收一次钱，10 个人都可以通过收银去吃饭。这时就要用到 ManualResetEvent，它的用法和 AutoResetEvent 基本一样，区别在于它一旦 Set 方法发出通知后，要再次阻塞的话就需要手动调用 Reset 方法。

总结

AutoResetEvent 和 ManualResetEvent 的主要区别：AutoResetEvent 一次只能通知一个等待线程，通知后自动关闭；ManualResetEvent 一次可通知很多个等待的线程，但关闭需要调用 Reset 方法手动关闭。

【补充】 现代 C# 中线程间通信/同步更推荐 TaskCompletionSource<T>（异步编程场景）、SemaphoreSlim、Channel<T>（生产者消费者）等，信号量类仍可了解原理。

8、线程同步

线程同步的几种方法

1、阻塞（Blocking）

当线程调用 Sleep、Join、EndInvoke，线程就处于阻塞状态（Sleep 使调用线程阻塞，Join、EndInvoke 使另外一个线程阻塞），会立即从 CPU 退出（阻塞状态的线程不消耗 CPU）。

2、加锁（lock）

加锁使多个线程同一时间只有一个线程可以调用该方法，其他线程被阻塞。

同步对象的选择：

  • 使用引用类型：值类型加锁时会装箱，产生一个新的对象，锁会失效；
  • 使用 private 修饰：使用 public 时易产生死锁（lock(this)、lock(typeof(实例)) 时，该类也应该是 private）；
  • string 不能作为锁对象；
  • 不能在 lock 中使用 await 关键字（C# 的 lock 语句不允许）。

锁是否必须是静态类型？

  • 如果被锁定的方法是静态的，那么这个锁必须是静态类型——全局锁定该方法，不管该类有多少个实例，都要排队执行；
  • 如果被锁定的方法不是静态的，那么不能使用静态类型的锁：被锁定的方法属于实例，只要该实例调用锁定方法不产生损坏就可以，不同实例间不需要锁。这个锁只锁该实例的方法，而不是锁所有实例的方法。
class ThreadSafe
{
    private static object _locker = new object();

    void Go()
    {
        lock (_locker)
        {
            // 共享数据的操作（Static Method），使用静态锁确保所有实例排队执行
        }
    }

    private object _locker2 = new object();
    void GoTo()
    {
        lock (_locker2)
        {
            // 共享数据的操作，非静态方法，使用非静态锁，确保同一个实例的方法调用者排队执行
        }
    }
}

同步对象可以兼作 lock 的对象：

class ThreadSafe
{
    private List<string> _list = new List<string>();
    void Test()
    {
        lock (_list)
        {
            _list.Add("Item 1");
        }
    }
}

3、Monitors

lock 其实是 Monitor 的简洁写法：

lock (x)
{
    DoSomething();
}

两者其实是一样的：

System.Object obj = (System.Object)x;
System.Threading.Monitor.Enter(obj);
try
{
    DoSomething();
}
finally
{
    System.Threading.Monitor.Exit(obj);
}

【补充】 Monitor 比 lock 更灵活：Monitor.TryEnter(obj, timeout) 可带超时等待，避免无限期阻塞；lock 语句内部即为 Monitor.Enter + try/finally 的语法糖（C# 4 前为 Enter/Exit，注意异常时 Exit 的保证）。

4、互斥锁（Mutex）

互斥锁是一个互斥的同步对象，同一时间有且仅有一个线程可以获取它。可以实现进程级别上线程的同步。

class Program
{
    // 实例化一个互斥锁
    public static Mutex mutex = new Mutex();
    static void Main(string[] args)
    {
        for (int i = 0; i < 3; i++)
        {
            // 在不同的线程中调用受互斥锁保护的方法
            Thread test = new Thread(MutexMethod);
            test.Start();
        }
        Console.Read();
    }
    public static void MutexMethod()
    {
        Console.WriteLine("{0} 请求获取互斥锁", Thread.CurrentThread.Name);
        mutex.WaitOne();
        Console.WriteLine("{0} 已获取到互斥锁", Thread.CurrentThread.Name);
        Thread.Sleep(1000);
        Console.WriteLine("{0} 准备释放互斥锁", Thread.CurrentThread.Name);
        // 释放互斥锁
        mutex.ReleaseMutex();
        Console.WriteLine("{0} 已经释放互斥锁", Thread.CurrentThread.Name);
    }
}

互斥锁可以在不同的进程间实现线程同步——使用互斥锁实现一个一次只能启动一个应用程序的功能：

public static class SingleInstance
{
    private static Mutex m;

    public static bool IsSingleInstance()
    {
        // 是否需要创建一个应用
        Boolean isCreateNew = false;
        try
        {
            m = new Mutex(initiallyOwned: true, name: "SingleInstanceMutex", createdNew: out isCreateNew);
        }
        catch (Exception ex)
        {
        }
        return isCreateNew;
    }
}

互斥锁的带有三个参数的构造函数：

  1. initiallyOwned：如果为 true，互斥锁的初始状态就是被所实例化的线程所获取；否则实例化的线程处于未获取状态；
  2. name：该互斥锁的名字，在操作系统中只有一个命名为 name 的互斥锁。如果一个线程得到这个 name 的互斥锁，其他线程就无法得到，必须等待那个线程释放；
  3. createdNew：如果指定名称的互斥体已经存在就返回 false，否则返回 true。

5、信号和句柄（AutoResetEvent / ManualResetEvent）

lock 和 Mutex 可以实现线程同步，确保一次只有一个线程执行，但实现不了线程间的通信。如果线程需要相互通信，就要使用 AutoResetEvent、ManualResetEvent，通过信号来相互通信。它们都有两个状态：终止状态和非终止状态。只有处于非终止状态时，线程才可以阻塞（WaitOne）。

AutoResetEvent：

  • 构造函数可以传入一个 bool 参数：false 表示初始状态为非终止；true 表示终止状态，那么 WaitOne 方法就不会再阻塞线程了。但因为该类会自动将终止状态修改为非终止，所以之后再调用 WaitOne 方法就会被阻塞；
  • WaitOne：如果 AutoResetEvent 对象状态非终止，则阻塞调用该方法的线程；可以指定时间，若没有获取到信号，返回 false；
  • Set：释放被阻塞的线程，但一次只可以释放一个被阻塞的线程。
class ThreadSafe
{
    static AutoResetEvent autoEvent;
    static void Main()
    {
        // 使AutoResetEvent处于非终止状态
        autoEvent = new AutoResetEvent(false);
        Console.WriteLine("主线程运行...");
        Thread t = new Thread(DoWork);
        t.Start();
        Console.WriteLine("主线程sleep 1秒...");
        Thread.Sleep(1000);
        Console.WriteLine("主线程释放信号...");
        autoEvent.Set();
    }

    static void DoWork()
    {
        Console.WriteLine("  t线程运行DoWork方法，阻塞自己等待main线程信号...");
        autoEvent.WaitOne();
        Console.WriteLine("  t线程DoWork方法获取到main线程信号，继续执行...");
    }
}
// 输出
// 主线程运行...
// 主线程sleep 1秒...
//   t线程运行DoWork方法，阻塞自己等待main线程信号...
// 主线程释放信号...
//   t线程DoWork方法获取到main线程信号，继续执行...

ManualResetEvent：

AutoResetEvent 在调用 Set 方法后，会自动将信号由释放（终止）改为阻塞（非终止），一次只有一个线程会得到释放信号；而 ManualResetEvent 在调用 Set 方法后不会自动将信号改为阻塞，而是一直保持释放信号，使得一次有多个被阻塞线程运行；只能手动调用 Reset 方法将信号由释放（终止）改为阻塞（非终止），之后的线程调用 WaitOne 才会被再次阻塞。

public class ThreadSafe
{
    // 创建一个处于非终止状态的ManualResetEvent
    private static ManualResetEvent mre = new ManualResetEvent(false);
    static void Main()
    {
        for (int i = 0; i <= 2; i++)
        {
            Thread t = new Thread(ThreadProc);
            t.Name = "Thread_" + i;
            t.Start();
        }
        Thread.Sleep(500);
        Console.WriteLine("\n新线程的方法已经启动，且被阻塞，调用Set释放阻塞线程");
        mre.Set();
        Thread.Sleep(500);
        Console.WriteLine("\n当ManualResetEvent处于终止状态时，调用WaitOne方法的多线程，不会被阻塞。");
        for (int i = 3; i <= 4; i++)
        {
            Thread t = new Thread(ThreadProc);
            t.Name = "Thread_" + i;
            t.Start();
        }
        Thread.Sleep(500);
        Console.WriteLine("\n调用Reset方法，ManualResetEvent处于非阻塞状态，此时调用WaitOne方法的线程再次被阻塞");
        mre.Reset();
        Thread t5 = new Thread(ThreadProc);
        t5.Name = "Thread_5";
        t5.Start();
        Thread.Sleep(500);
        Console.WriteLine("\n调用Set方法，释放阻塞线程");
        mre.Set();
    }
    private static void ThreadProc()
    {
        string name = Thread.CurrentThread.Name;
        Console.WriteLine(name + " 运行并调用WaitOne()");
        mre.WaitOne();
        Console.WriteLine(name + " 结束");
    }
}
// Thread_2 运行并调用WaitOne()
// Thread_1 运行并调用WaitOne()
// Thread_0 运行并调用WaitOne()
// 新线程的方法已经启动，且被阻塞，调用Set释放阻塞线程
// Thread_2 结束
// Thread_1 结束
// Thread_0 结束
// 当ManualResetEvent处于终止状态时，调用WaitOne方法的多线程，不会被阻塞。
// Thread_3 运行并调用WaitOne()
// Thread_4 运行并调用WaitOne()
// Thread_4 结束
// Thread_3 结束
// 调用Reset方法，ManualResetEvent处于非阻塞状态，此时调用WaitOne方法的线程再次被阻塞
// Thread_5 运行并调用WaitOne()
// 调用Set方法，释放阻塞线程
// Thread_5 结束

6、Interlocked（原子操作）

如果一个变量被多个线程修改、读取，可以用 Interlocked。

计算机上不能保证对一个数据的增减是原子性的，因为对数据的操作也是分步骤的：

  1. 将实例变量中的值加载到寄存器中；
  2. 增加或减少该值；
  3. 在实例变量中存储该值。

Interlocked 为多线程共享的变量提供原子操作。常用方法：

  • public static int Add(ref int location1, int value);：两个参数相加，且把结果赋值给第一个参数；
  • public static int Increment(ref int location);：自增；
  • public static int CompareExchange(ref int location1, int value, int comparand);：location1 和 comparand 比较，如果相等，就把 value 赋值给第一个参数。

【补充】 除 int 外还支持 long、double、引用类型等重载；Interlocked.Exchange 可原子交换值。现代代码中很多场景可用 volatile、lock 或原子类替代。

7、ReaderWriterLock（读写锁）

如果要确保一个资源或数据在被访问之前是最新的，可以使用 ReaderWriterLock。该锁确保在对资源赋值或更新时，只有它自己可以访问这些资源，其他线程都不可以访问，即排他锁。但用该锁读取这些数据时，不能实现排他锁。

lock 允许同一时间只有一个线程执行；而 ReaderWriterLock 允许同一时间有多个线程可以执行读操作，或者只有一个有排他锁的线程执行写操作。

class Program
{
    // 创建一个对象
    public static ReaderWriterLock readerwritelock = new ReaderWriterLock();
    static void Main(string[] args)
    {
        // 创建一个线程读取数据
        Thread t1 = new Thread(Write);
        // t1.Start(1);
        Thread t2 = new Thread(Write);
        // t2.Start(2);
        // 创建10个线程读取数据
        for (int i = 3; i < 6; i++)
        {
            Thread t = new Thread(Read);
            // t.Start(i);
        }
        Console.Read();
    }
    // 写入方法
    public static void Write(object i)
    {
        // 获取写入锁，20毫秒超时。
        Console.WriteLine("线程：" + i + "准备写...");
        readerwritelock.AcquireWriterLock(Timeout.Infinite);
        Console.WriteLine("线程：" + i + " 写操作" + DateTime.Now);
        // 释放写入锁
        Console.WriteLine("线程：" + i + "写结束...");
        Thread.Sleep(1000);
        readerwritelock.ReleaseWriterLock();
    }
    // 读取方法
    public static void Read(object i)
    {
        Console.WriteLine("线程：" + i + "准备读...");
        // 获取读取锁，20毫秒超时
        readerwritelock.AcquireReaderLock(Timeout.Infinite);
        Console.WriteLine("线程：" + i + " 读操作" + DateTime.Now);
        // 释放读取锁
        Console.WriteLine("线程：" + i + "读结束...");
        Thread.Sleep(1000);
        readerwritelock.ReleaseReaderLock();
    }
}

分别屏蔽 writer 和 reader 方法，可以更清晰地看到：屏蔽 reader 时，writer 被阻塞；屏蔽 writer 时，reader 没有被阻塞（多个 reader 可同时读）。

【补充】 现代代码优先使用 ReaderWriterLockSlim（性能更好、支持升级锁、超时）；写少读多场景收益最大。亦可考虑 SemaphoreSlim、ConcurrentDictionary 等无锁/并发集合。

9、WPF

9.1 WPF 由哪两部分组成？

WPF 由两个主要部分组成：引擎和编程框架。

  1. 引擎：WPF 引擎为基于窗体的应用程序的图形、视频、音频和文档提供了一个单一的运行时库。重要的是 WPF 基于矢量的呈现引擎使应用程序可以灵活地利用高 DPI 监视器，支持图形的硬件加速。
  2. 框架：WPF 框架为媒体、用户界面设计和文档提供大量的解决方案。WPF 的设计考虑了可扩展性，使开发人员可以完全在 WPF 引擎的基础上创建自己的控件，也可以通过对现有 WPF 控件进行再分类来创建自己的控件。

9.2 什么是 WPF？

WPF 英文全称是 Windows Presentation Foundation，中文为 Windows 表现层基础。是微软最初在 .NET Framework 3.5 平台推出的一个图形平台。

9.3 Silverlight 和 WPF 的异同？

运行方式不同：

  1. Silverlight 是基于浏览器插件的，在浏览器中运行；
  2. WPF 可以编写 Web 程序或者桌面应用程序，可以直接编译为独立运行的 exe 文件。

实现功能不同：

  1. WPF 支持直接在 XAML 中绑定触发器来触发动画，而 Silverlight 就只能通过托管代码或者 JavaScript 来进行；
  2. WPF 直接支持 3D 效果和 3D 镜头变换，但是 Silverlight 不支持。

相似的地方：

Silverlight 原名 WPF/E（WPF Everywhere），是 WPF 的一个子集。因此它们在很多语法实现上非常类似。

【补充】 Silverlight 已于 2021 年 10 月正式停止支持（.NET Core/.NET 5+ 不再包含），了解历史概念即可，无需深究。

9.4 如何理解 WPF 体系结构？

WPF 使用多层架构，类似于三层结构：最顶层部分为托管代码 API，此层用于为开发人员编写 WPF 应用程序提供较高层次的服务，基于 C# 托管代码编写。转换 .NET 代码到 DirectX 的工作由中间层 milcore.dll 实现。

中间层 milcore 是用非托管代码实现，因为它需要与 DirectX 紧密集成，对性能敏感，消耗的资源比较多，对性能影响较大。

9.5 在 WPF 中 Binding 的作用及实现语法？

典型的 Binding 具有四个重要组成部分：Binding 目标对象（binding target object）、目标对象属性（target property）、Binding 数据源（binding source）、Path（用于指明要从数据源中取得的值，就是我们通常写的属性名称）。

【补充】 最小示例：<TextBlock Text="{Binding UserName}" />，目标属性必须是依赖属性；可通过 UpdateSourceTrigger（默认 PropertyChanged/ LostFocus 因绑定模式而异）、Mode（OneWay/TwoWay/OneTime/OneWayToSource）控制行为。

9.6 什么是 XML 扩展 XAML？有何优点？

  1. XAML 是 eXtensible Application Markup Language 的英文缩写，相应于中文称为可扩展应用程序标记语言，它是微软公司为构建应用程序用户界面而创建的一种新的描述性语言；
  2. XAML 是 XML 语言的一个衍生物，它的语法与 XML 语言完全一致，它的功能就是专门用来设计和实现程序的 UI；
  3. XAML 一个很大的优点就是由于 WPF 支持 WEB 开发，那么 WEB 开发和桌面开发的转换是很简单，修改的地方很短，同时 UI 与逻辑完全分离，所以逻辑代码也几乎不用改动。

【补充】 XAML 采用"声明式 UI"：.xaml（界面）+ .xaml.cs（code-behind 逻辑）编译为 partial 类；支持数据绑定、样式、模板、动画等特性深度集成；WPF/UWP/WinUI/MAUI 均沿用 XAML 思想。

9.7 解释什么是依赖属性，它和以前的属性有什么不同？为什么在 WPF 会使用它？

  1. Windows Presentation Foundation (WPF) 提供了一组服务，这些服务可用于扩展公共语言运行时 (CLR) 属性的功能，这些服务通常统称为 WPF 属性系统。由 WPF 属性系统支持的属性称为依赖项属性。

  2. 它和以往属性的不同之处：

    （1）依赖属性是一种特定类型的属性，其属性值受到 Windows 运行时中专用属性系统的跟踪和影响；

    （2）依赖属性的用途是提供一种系统的方式，用来基于其他输入（在应用运行时其内部出现的其他属性、事件和状态）计算属性的值；

    （3）依赖属性代表或支持编程模型的某种特定功能，用于定义 Windows 运行时应用，这种模型使用 XAML 编写 UI，使用 C# 编写代码。一般的属性没有这么复杂。

  3. WPF 使用它的优点：

    （1）优化了属性的存储，直接减少了不必要的内存使用（未赋值的属性不占实例空间）；

    （2）有属性变化通知、限制、验证等；

    （3）可以储存多个值，配合 Expression 及 Animation 等，打造出更灵活的使用方法。

【补充】 依赖属性还支持属性值继承（如沿逻辑树继承 DataContext）、样式/模板/触发器/动画统一接入；通过 DependencyProperty.Register 注册，用 GetValue/SetValue 读写。示例：

public static readonly DependencyProperty TitleProperty =
    DependencyProperty.Register("Title", typeof(string), typeof(MyControl),
        new PropertyMetadata(string.Empty, OnTitleChanged));
public string Title
{
    get => (string)GetValue(TitleProperty);
    set => SetValue(TitleProperty, value);
}

9.8 WPF 中什么是样式？

  • 首先明白 WPF 中样式属于资源中重要的一种；
  • 样式也是属性值的集合，能被应用到一个合适的元素中，或者说能将一组属性应用到多个元素；
  • WPF 中样式可以设置任何依赖属性；
  • WPF 中样式也支持触发器，通过属性的改变，触发一组活动，包括改变某个控件的样式；
  • WPF 中元素只能使用一个样式（可通过 BasedOn 实现样式继承，样式可以继承样式）。
<Style x:Key="MyButtonStyle" TargetType="Button">
    <Setter Property="Width" Value="80" />
    <Setter Property="Height" Value="40" />
    <Style.Triggers>
        <Trigger Property="IsMouseOver" Value="True">
            <Setter Property="Background" Value="LightGreen" />
        </Trigger>
    </Style.Triggers>
</Style>

9.9 WPF 中什么是模板？

WPF 中模板是用于定义或重定义控件结构，或者说对象的外观。

WPF 中模板有两类，一个是控件模板（ControlTemplate），另一个是数据模板（DataTemplate），它们都派生自 FrameworkTemplate 抽象类。总共有三大模板：ControlTemplate、ItemsPanelTemplate、DataTemplate。

  1. ControlTemplate 主要用途是更改控件的外观。它有两个重要属性：VisualTree（视觉树）内容属性和 Triggers 触发器。VisualTree 就是呈现我们所画的控件，Triggers 可以对视觉树上的元素进行一些变化；
  2. ItemsPanelTemplate 是个特殊的空间模板，主要用来标明多条目控件如何显示它所包含的多项数据，也可以说是指定用于项的布局的面板，多用于多个内容控件的目标（如 ListBox 的 ItemsPanel）；
  3. DataTemplate 主要用于数据的呈现，也被称为显示绑定数据对象的模板。

数据是如何显示出来的？虽然数据模板定义了数据的可视结构，但是只有控件才是可视的，数据一般是被控件承载，这里需要另外的一个对象 ContentPresenter（内容呈现器）。

9.10 绑定（Binding）的基础用法

WPF 里分三种：Binding、PriorityBinding、MultiBinding，这三种 Binding 的基类都是 BindingBase，而 BindingBase 又继承于 MarkupExtension。

常见的使用 Binding 方法：

  1. 针对于继承于 FrameworkElement 的控件：SetBinding(DependencyProperty dp, string path)、SetBinding(DependencyProperty dp, BindingBase binding)——FrameworkElement 中 SetBinding 只对 DependencyProperty 有效；
  2. 另一种是 BindingOperations.SetBinding(currentFolder, TextBlock.TextProperty, binding)：
public static BindingExpressionBase SetBinding(DependencyObject target, DependencyProperty dp, BindingBase binding)
  1. 清除 Binding：
BindingOperations.ClearBinding(currentFolder, TextBlock.TextProperty); // 删除currentFolder上的TextBlock.TextProperty绑定
BindingOperations.ClearAllBindings(currentFolder);                     // 删除currentFolder上的所有绑定

直接对 Dependency Property 赋值也可以解除 Binding，不过只对单向 Binding 有效。

9.11 解释这几个类的作用及关系：Visual、UIElement、FrameworkElement、Control

它们四者的继承关系（原文方向写反，此处已修正）：

Control → FrameworkElement → UIElement → Visual → DependencyObject

即：Control 继承 FrameworkElement，FrameworkElement 继承 UIElement，UIElement 继承 Visual，Visual 继承 DependencyObject。

各层作用：

  1. Visual：为 WPF 提供 2D 呈现支持，主要包括输出显示、坐标转换、区域剪切等；
  2. UIElement：构建 WPF 元素和基本呈现特征的基类，定义了很多与输入和焦点有关的特性，例如键盘事件、鼠标事件，以及与 WPF 事件模型（路由事件）有关的 API；
  3. FrameworkElement：为 WPF 元素添加功能，例如布局定义（Measure/Arrange）、逻辑树、对象生命周期事件、支持数据绑定和动态资源引用、支持样式和动画；
  4. Control：为自定义应用程序控件提供基础，是创建自定义应用程序控件的基类，可以重写 Control 类所提供的属性、方法、事件等，为自定义控件添加自定义逻辑。构建 WPF 应用程序页面的 Window 类也派生自它（Window → ContentControl → Control）。

【补充】 这一继承链是 WPF 高频考点，务必按正确顺序记忆；ContentControl（可承载内容）、ItemsControl（可承载多项）均继承自 Control。

9.12 视觉树 VS 逻辑树

  1. 逻辑树是视觉树的子集，视觉树基本上是逻辑树的一种扩展；
  2. WPF 通过逻辑树来解决依赖项属性继承和资源的问题，使用视觉树来处理渲染、事件路由、资源定位等问题；
  3. 逻辑树可以认为是 XAML 所见的元素结构，而视觉树包含了 XAML 元素内部的结构（如 Border、ContentPresenter 等模板生成元素）；
  4. 逻辑树的查找可以通过 LogicalTreeHelper 辅助类，视觉树的查找可以通过 VisualTreeHelper 辅助类。注意：对 ContentElement 元素的查找，无法直接通过 VisualTreeHelper 进行，ContentElement 并不继承 Visual，其使用时需要一个 ContentElement 载体 FrameworkContentElement。

附：属性变更通知（INotifyPropertyChanged 和 ObservableCollection）

  1. INotifyPropertyChanged 向客户端发出某一属性值更改的通知；
  2. ObservableCollection<T> 类是实现 INotifyCollectionChanged 接口的数据集合的内置实现，表示一个动态数据集合，在添加项、移除项或刷新整个列表时，此集合将提供通知。

【补充】 二者是 WPF/MVVM 数据绑定自动刷新的基础：

public class Person : INotifyPropertyChanged
{
    private string _name;
    public string Name
    {
        get => _name;
        set { _name = value; OnPropertyChanged(nameof(Name)); }
    }
    public event PropertyChangedEventHandler PropertyChanged;
    private void OnPropertyChanged(string propName) =>
        PropertyChanged?.Invoke(this, new PropertyChangedEventArgs(propName));
}

注意：ObservableCollection<T> 增删会自动刷新 UI，但修改集合中某个元素的属性仍需该元素实现 INotifyPropertyChanged；List<T> 无变更通知，绑定后 UI 不会自动更新。

9.13 解释一下 ResourceDictionary？

提供包含元素和 WPF 应用程序的其他元素使用的 WPF 资源的一个哈希表/字典实现，有利于项目中资源共享。

【补充】 资源查找沿逻辑树向上：元素自身 → 父级 → Application → 系统资源；可在 App.xaml 中合并（MergedDictionaries）实现跨窗口共享；StaticResource 编译期解析、DynamicResource 运行期可变更。

9.14 路由事件的哪三种方式/策略（冒泡、直接、隧道）？

WPF 中的路由事件是沿着 VisualTree 传递的，作用是用来调用应用程序的元素树上的各种监听器上的处理程序。

  1. 冒泡（Bubbling）：从源元素向上级流过去，直到到达根节点即顶层节点，一般为最外层的控件；
  2. 直接（Direct）：在源上处理，主要用在源元素上处理；
  3. 隧道（Tunneling）：又称 Preview 事件，和冒泡事件处理方式相反——从元素树的根位置调用事件处理程序，依次向下直到源元素位置。

隧道事件和冒泡事件一般成对出现（如 PreviewMouseDown/MouseDown）。同一事件执行时首先是隧道事件，然后是冒泡事件。

【补充】 事件签名惯例：AddHandler/RemoveHandler 订阅路由事件，e.Handled = true 可停止继续路由；RaiseEvent 可手动触发。

9.15 解释 Routed Events（路由事件）与 Commands（命令）？

Event 和 Command 是程序内部通信基础：Routed Events 能够发起多重控件，并且能有序和用户沟通；Commands 是 .NET Framework 提供的核心架构，用来激活和去除高级别任务。由此衍生的 Animation 是 Events 的更进一步，让你能够以友好互动的方式使用 Event 架构来使用多重控件。

【补充】 更清晰的理解：

  • 路由事件：解决"事件沿元素树传递"的问题——子控件的事件可以让父级（或命令系统）处理，适合 UI 输入事件（点击、键盘等）；
  • 命令（ICommand）：把"动作意图"与"具体执行"解耦——命令包含 CanExecute（是否可用）与 Execute（执行），可统一启用/禁用（如"保存"按钮与菜单项共享同一命令），可集中做权限控制、撤销等；MVVM 中 ViewModel 通过命令暴露操作，View 用 {Binding 命令属性} 绑定。
public class RelayCommand : ICommand
{
    private readonly Action _execute;
    private readonly Func<bool> _canExecute;
    public RelayCommand(Action execute, Func<bool> canExecute = null)
    { _execute = execute; _canExecute = canExecute; }
    public bool CanExecute(object p) => _canExecute == null || _canExecute();
    public void Execute(object p) => _execute();
    public event EventHandler CanExecuteChanged;
}

9.16 模板（详解）

WPF 模板有三种：ControlTemplate、DataTemplate、ItemsPanelTemplate，它们都继承自 FrameworkTemplate 抽象类。在这个抽象类中有一个 FrameworkElementFactory 类型的 VisualTree 变量，通过该变量可以设置或者获取模板的根节点，包含了你想要的外观元素树。

（1）控件模板：控件模板可以将自定义模板应用到某一特定类型的所有控件，或是控件的某一实例。决定控件外观的是 ControlTemplate，它决定了控件"长成什么样子"。控件模板实际在资源集合或资源字典中定义。

（2）数据模板：决定数据外观的是 DataTemplate，即 DataTemplate 是数据内容的表现形式——一条数据显示成什么样子，是简单的文本还是直观的图形，由 DataTemplate 决定。

（3）ItemsPanelTemplate 模板：指定用于项的布局的面板，如通过设置 ListBox 的 ItemsPanelTemplate，使得每一项从左至右按顺序显示。

1、ControlTemplate

控件模板主要有两个重要属性：VisualTree 内容属性和 Triggers 触发器。所谓 VisualTree（视觉树），就是呈现我们所画的控件；Triggers 可以对我们的视觉树上的元素进行一些变化。一般用于单内容控件。

<Button Content="确定">
    <Button.Template>
        <ControlTemplate TargetType="Button">
            <Border x:Name="bd" Background="LightBlue" CornerRadius="5" Padding="10,5">
                <ContentPresenter />
            </Border>
            <ControlTemplate.Triggers>
                <Trigger Property="IsMouseOver" Value="True">
                    <Setter TargetName="bd" Property="Background" Value="Orange" />
                </Trigger>
            </ControlTemplate.Triggers>
        </ControlTemplate>
    </Button.Template>
</Button>

2、ItemsPanelTemplate

ItemsPanelTemplate 指定用于项的布局的面板。GroupStyle 具有一个类型为 ItemsPanelTemplate 的 Panel 属性；ItemsControl 类型具有一个类型为 ItemsPanelTemplate 的 ItemsPanel 属性。它一般用在多个内容控件的模板，比如 ListBox。

<ListBox>
    <ListBox.ItemsPanel>
        <ItemsPanelTemplate>
            <StackPanel Orientation="Horizontal" />
        </ItemsPanelTemplate>
    </ListBox.ItemsPanel>
</ListBox>

3、DataTemplate 和 HierarchicalDataTemplate

DataTemplate 就是显示绑定数据对象的模板。虽然某数据是一定的，但我们可以让它的表现方式多种多样。

HierarchicalDataTemplate 继承于 DataTemplate，它专门用于 TreeViewItem 或 MenuItem 等层级数据对象的绑定。

<DataTemplate DataType="{x:Type local:Person}">
    <StackPanel Orientation="Horizontal">
        <TextBlock Text="{Binding Name}" FontWeight="Bold" />
        <TextBlock Text="{Binding Age}" Foreground="Gray" />
    </StackPanel>
</DataTemplate>

9.17 触发器

WPF 中的触发器是对 WPF 事件的一种封装，有多种方式，总结起来可分为：

  • 控件触发（FrameworkElement.Triggers 集合）
  • 样式触发（Styles.Triggers 集合）
  • 控件模板触发（ControlTemplate.Triggers 集合）
  • 数据模板触发（DataTemplate.Triggers 集合）

触发器种类：

  • System.Windows.DataTrigger 数据触发器
  • System.Windows.EventTrigger 事件触发器
  • System.Windows.MultiDataTrigger 多数据触发器
  • System.Windows.MultiTrigger 多属性触发器
  • System.Windows.Trigger 属性触发器

1、属性触发器 Trigger

属性触发器是由属性的改变而引起的，几个关键属性：

  • Property：获取或设置返回的值进行比较的属性（只有依赖属性才有用）；
  • Value：获取或设置要与该元素的属性值进行比较的值（比较是引用相等性检查）；
  • Setter：获取一套 Setter 对象，描述要应用当满足指定条件时的属性值（Setter 属性是一个 SetterBaseCollection 的集合）。

Setter 类： Property（其 Value 将被应用的属性，只有依赖属性才有用）、Value（要应用于指定属性的值）。

<Button Content="触发器" x:Name="btn1" Click="Button_Click">
    <Button.Style>
        <Style>
            <Setter Property="Button.Width" Value="80"></Setter>
            <Setter Property="Button.Height" Value="100"></Setter>
            <Style.Triggers>
                <Trigger Property="Button.IsMouseOver" Value="true">
                    <Trigger.Setters>
                        <Setter Property="Button.Width" Value="200"></Setter>
                    </Trigger.Setters>
                </Trigger>
            </Style.Triggers>
        </Style>
    </Button.Style>
</Button>

2、多属性触发器 MultiTrigger

多属性触发器，是一个或者多个属性发生变化时，才会触发的触发器。其有一个重要属性 Condition（MultiTrigger.Conditions 是一个 Condition 的集合），用于统计条件：

<Style>
    <Setter Property="Button.Width" Value="80"></Setter>
    <Setter Property="Button.Height" Value="100"></Setter>
    <Style.Triggers>
        <MultiTrigger>
            <MultiTrigger.Conditions>
                <Condition Property="Control.IsFocused" Value="true"></Condition>
                <Condition Property="Control.IsMouseOver" Value="true"></Condition>
            </MultiTrigger.Conditions>
            <Setter Property="Button.Width" Value="300"></Setter>
        </MultiTrigger>
    </Style.Triggers>
</Style>

3、事件触发器 EventTrigger

事件触发器是由控件的操作触发的信息。EventTrigger 几个关键属性：

  • RoutedEvent：获取或设置将激活该触发器的 RoutedEvent；
  • Actions：获取事件发生时要应用的操作的集合（TriggerActionCollection）。

事件触发器只能调用 CallMethodAction、PlaySoundAction、StoryboardAction、InvokeCommandAction 等动作，所以事件触发器一般应用于动画中（以 StoryboardAction 为例，其封装了动作 BeginStoryboard，相当于调用 BeginAnimation 方法）：

<Button Content="触发器" x:Name="btn1" Click="Button_Click">
    <Button.Style>
        <Style>
            <Setter Property="Button.Width" Value="80"></Setter>
            <Setter Property="Button.Height" Value="80"></Setter>
            <Style.Triggers>
                <EventTrigger RoutedEvent="Button.Click">
                    <EventTrigger.Actions>
                        <BeginStoryboard>
                            <Storyboard>
                                <DoubleAnimation Storyboard.TargetProperty="Width"
                                                 To="300" Duration="0:0:1" />
                            </Storyboard>
                        </BeginStoryboard>
                    </EventTrigger.Actions>
                </EventTrigger>
            </Style.Triggers>
        </Style>
    </Button.Style>
</Button>

4、数据触发 DataTrigger

数据触发器在数据改变时触发。DataTrigger 有两个重要的属性：

  • Binding：获取或设置产生数据对象的属性值的绑定；
  • Value：获取或设置要与此数据对象的属性值进行比较的值。
<Style>
    <Style.Triggers>
        <DataTrigger Binding="{Binding RelativeSource={RelativeSource Self}, Path=Text}" Value="8">
            <Setter Property="Button.Foreground" Value="Sienna"></Setter>
            <Setter Property="Button.FontWeight" Value="Bold"></Setter>
            <Setter Property="Button.FontSize" Value="30"></Setter>
        </DataTrigger>
    </Style.Triggers>
</Style>

5、多数据触发器 MultiDataTrigger

多数据触发器是对数据触发器的扩展，需要同时满足多个数据改变的情况下才执行。

触发器使用场景分类表（有些触发器在有的触发方式中可以使用，但并不代表一定有作用，使用中根据情况进行区分）：

触发方式 可使用的触发器 说明
控件触发 必须使用 EventTrigger 用于调整界面、实现动画等
样式触发 Trigger、EventTrigger、MultiTrigger、DataTrigger、MultiDataTrigger 可使用所有触发器
控件模板触发 Trigger、EventTrigger、MultiTrigger、DataTrigger、MultiDataTrigger 可使用所有触发器
数据模板触发 Trigger、EventTrigger、MultiTrigger、DataTrigger、MultiDataTrigger 可使用所有触发器
